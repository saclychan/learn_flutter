# Performance Monitoring: Từ Newbie đến Senior 🏎️💨

## 1. Mở Đầu
App của bạn chạy ngon trên máy ảo iPhone 15 Pro Max của bạn không có nghĩa là nó mượt trên con máy Android giá rẻ RAM 2GB của user. 
Performance Monitoring (VD: Firebase Performance Monitoring, Sentry) giúp bạn đo lường:
- App khởi động mất bao lâu?
- API nào đang phản hồi chậm rùa bò?
- Màn hình nào render bị rớt frame (jank)?

## 2. Setup Cơ Bản (Newbie)
Với Firebase, thêm package:
```bash
flutter pub add firebase_performance
```
Mặc định, Firebase Performance sẽ tự động đo thời gian khởi động app và screen rendering (tuy nhiên trên Flutter, bạn phải tích hợp thêm chút cấu hình navigator observer để đo màn hình).

Đo thời gian chạy của một hàm cụ thể (Custom Trace):
```dart
import 'package:firebase_performance/firebase_performance.dart';

Future<void> processHeavyData() async {
  Trace trace = FirebasePerformance.instance.newTrace('heavy_data_processing');
  await trace.start();

  // Chạy logic nặng...
  await Future.delayed(Duration(seconds: 2));

  await trace.stop();
}
```

## 3. Senior Detail & Fun Fact 🧠
- **Senior Detail**: HTTP/Network tracing là thứ quan trọng nhất. Nếu app giật lác, 90% là do list view bị rebuild ngu ngốc, 10% do API chậm. Firebase Perf có thể tự động track HTTP request nếu bạn dùng `http` package, nhưng với `dio`, bạn cần thêm interceptor!
- **Fun Fact**: Mắt người nhận biết được sự giật lag nếu khung hình tụt xuống dưới 60 FPS (tương đương 16.6ms cho mỗi frame). Nếu code UI của bạn mất hơn 16ms để render, app sẽ bị "Jank".

## 4. Google Style Guide Advice 📐
> *"Khi thực hiện các thao tác tốn thời gian (I/O, database, API), luôn luôn đẩy chúng ra khỏi Main Isolate bằng cách sử dụng `compute` hoặc `Isolate.run` để không block UI thread."*

## 5. Nỗi Đau Junior (Junior Pitfalls) 🤦‍♂️
### ❌ Sai Lầm (Code Bốc Mùi)
Đo hiệu năng bằng... `print` 😭
```dart
void loadData() {
  var start = DateTime.now();
  fetchData();
  var end = DateTime.now();
  print('Thời gian chạy: ${end.difference(start).inMilliseconds}'); // ❌ Chỉ xem được trên máy mình!
}
```

### ✅ Đúng (Code Senior)
```dart
Future<void> loadData() async {
  Trace trace = FirebasePerformance.instance.newTrace('fetch_home_data');
  await trace.start();
  
  try {
    await fetchData();
  } finally {
    await trace.stop(); // ✅ Đảm bảo luôn được stop dù có lỗi
  }
}
```

## 6. 🐛 Thử Thách Gỡ Lỗi (Debugging Challenge)
Dưới đây là một đoạn code để monitor API call bằng Dio Interceptor nhưng có một lỗi nghiêm trọng:
```dart
class PerfInterceptor extends Interceptor {
  HttpMetric? metric;

  @override
  void onRequest(RequestOptions options, RequestInterceptorHandler handler) {
    metric = FirebasePerformance.instance.newHttpMetric(options.path, HttpMethod.Get);
    metric?.start();
    handler.next(options);
  }

  @override
  void onResponse(Response response, ResponseInterceptorHandler handler) {
    metric?.httpResponseCode = response.statusCode;
    metric?.stop();
    handler.next(response);
  }
}
```
**Nhiệm vụ của bạn**: Nếu có 2 API gọi CÙNG LÚC (concurrently), điều tồi tệ gì sẽ xảy ra với biến `metric`? Làm thế nào để sửa nó?
*Gợi ý*: State của Interceptor!

## 7. 🚀 System Design Challenge
**App Báo Cáo Chậm Chạp**
Hãy thiết kế (và code) một cơ chế:
1. Mỗi khi gọi 1 API, sử dụng `Stopwatch`.
2. Nếu API mất hơn 3 giây để hoàn thành, hãy tự động ghi log lỗi non-fatal lên Firebase Crashlytics với nội dung: "API X phản hồi quá chậm".
3. Add Dio Interceptor thực hiện việc này một cách tự động cho toàn bộ app mà không phải viết lại code ở từng API call.
