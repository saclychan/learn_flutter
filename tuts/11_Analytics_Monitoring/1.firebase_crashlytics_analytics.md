# Bài 1: Bắt Lỗi và Log Hành Vi (Crashlytics & Analytics)

App của bạn chạy ngon trên máy Emulator. Bạn hào hứng đẩy lên Store. Vài hôm sau, User để lại review 1 sao: "App rác, vừa vào đã văng". Chuyện gì đã xảy ra? Giao diện lỗi, API sập, hay máy của họ hết RAM?

Làm sao bạn fix được lỗi khi bạn KHÔNG BIẾT nó là lỗi gì? Chào mừng đến với Firebase Crashlytics.

> 💡 **Fun Fact:** Crashlytics không chỉ lưu lại dòng code bị lỗi (Stack trace). Nếu bạn cấu hình tốt, nó còn ghi nhận cả trạng thái RAM, mức Pin, hệ điều hành thiết bị lúc xảy ra sự cố, và cả những thao tác cuối cùng của người dùng trước khi App "đột tử"!

## 1. Firebase Crashlytics (Bác sĩ cấp cứu)
Cấu hình Crashlytics cực kỳ đơn giản. Đừng quên đặt nó vào trong `main.dart` để "bao trọn" cả App.

```dart
void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await Firebase.initializeApp();

  // Bắt mọi lỗi do Flutter framework văng ra (Lỗi UI, Render)
  FlutterError.onError = FirebaseCrashlytics.instance.recordFlutterFatalError;

  // Bắt mọi lỗi do logic Dart bất đồng bộ (Exception, API error)
  PlatformDispatcher.instance.onError = (error, stack) {
    FirebaseCrashlytics.instance.recordError(error, stack, fatal: true);
    return true;
  };

  runApp(MyApp());
}
```
**Chủ động gửi lỗi:** Đôi khi App không sập, nhưng API trả về sai logic. Bạn muốn ghi nhận lại để theo dõi:
```dart
try {
  // Logic gọi API
} catch (e, stackTrace) {
  FirebaseCrashlytics.instance.recordError(e, stackTrace, reason: 'Lỗi parse JSON API giỏ hàng');
}
```

## 2. Firebase Analytics (Nhà phân tích Hành vi)
Làm sao Marketing biết tính năng "Lắc xí ngầu" của bạn có ai xài không? Bạn phải theo dõi sự kiện (Event Tracking).

```dart
// Log một event đơn giản
await FirebaseAnalytics.instance.logEvent(
  name: "shake_dice",
  parameters: {
    "result_score": 6,
    "user_tier": "VIP"
  },
);
```

> 🧠 **Senior Detail:** Việc rải hàm `logEvent` khắp nơi trong code UI làm code nát bét. Senior sẽ tạo một Mixin hoặc một Analytics Service riêng biệt, và ném việc bắn Event vào trong `BlocListener` hoặc `Router` (Log việc chuyển màn hình tự động).

## 🛑 Những nỗi đau và ngộ nhận khi còn Junior
- **Đọc Stack Trace mù tịt trên iOS:** Junior thấy lỗi Crashlytics báo từ thiết bị iOS toàn mã Hexa (VD: `0x0000001ABC`). Khóc thét vì không biết dòng code nào. **Cách phòng tránh:** Trên iOS, code bị nén lại thành mã máy. Phải upload thư mục dSYM (Debug Symbols) lên Firebase để nó giải mã ngược (de-obfuscate) ra lại dòng code Dart! Fastlane có thể giúp bạn tự động hóa việc này.
- **Log Event quá muộn:** Tính năng X ra mắt 1 tháng mới nhớ chưa cắm Analytics. Mất sạch dữ liệu thống kê. **Cách phòng tránh:** Kỹ năng của Senior: Code Logic đi đôi với Cắm Log. Coi Analytics như một phần của tính năng.

### 🚀 Mini Pet Project: Siêu Mẫu Báo Cáo Sự Cố

**Yêu cầu:**
1. Tạo Firebase Project, cài đặt FlutterFire, bật Crashlytics trong console. Thêm gói `firebase_crashlytics` và `firebase_analytics`.
2. Gắn đoạn code bắt lỗi tự động vào hàm `main()`.
3. Tạo 2 nút bấm ở UI:
   - Nút 1: "Tạo Fatal Error". Khi bấm, chủ động quăng lỗi: `throw Exception('Tôi cố tình làm hỏng App!');`
   - Nút 2: "Log Event". Gọi Analytics log 1 sự kiện `button_clicked`.
4. Build App ra máy ảo. Bấm nút 1 cho app văng.
5. Lên Firebase Console -> Crashlytics. Bạn sẽ thấy dòng code của mình nằm chễm chệ ở đó cùng với tên chiếc điện thoại vừa bị văng!
