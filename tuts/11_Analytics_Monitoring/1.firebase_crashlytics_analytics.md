# Firebase Crashlytics & Analytics: Từ Newbie đến Senior 📊💥

## 1. Mở Đầu (Tại sao lại cần cái này?)
Khi app release ra store, bạn không thể cắm cáp vào điện thoại của hàng ngàn user để xem `print()` hay đọc log lỗi được. 
- **Analytics**: Giúp bạn trả lời câu hỏi "User đang làm gì trong app? Họ bấm nút A hay nút B nhiều hơn?".
- **Crashlytics**: Cứu tinh đời bạn! Giúp bạn biết chính xác dòng code nào làm app văng (crash) trên thiết bị của user.

## 2. Setup Cơ Bản (Dành cho Newbie)
Để tích hợp, bạn cần add các package:
```bash
flutter pub add firebase_core firebase_analytics firebase_crashlytics
```

Khởi tạo trong `main.dart`:
```dart
import 'package:flutter/material.dart';
import 'package:firebase_core/firebase_core.dart';
import 'package:firebase_crashlytics/firebase_crashlytics.dart';

void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await Firebase.initializeApp();
  
  // Pass all uncaught "fatal" errors from the framework to Crashlytics
  FlutterError.onError = FirebaseCrashlytics.instance.recordFlutterFatalError;

  runApp(const MyApp());
}
```

## 3. Senior Detail & Fun Fact 🧠
- **Senior Detail**: Đừng log mọi thứ! Việc bắn quá nhiều event lên Analytics không chỉ tốn băng thông, hao pin của user mà còn làm "rác" dashboard của Data Analyst. Hãy log những thứ có chủ đích.
- **Fun Fact**: Crashlytics tự động gom nhóm (grouping) các lỗi giống nhau dựa trên stack trace, nên bạn không bị "spam" hàng ngàn email cho cùng 1 lỗi.

## 4. Google Style Guide Advice 📐
> *"Tránh sử dụng `print` trong production code. Hãy sử dụng một logging framework như `logging` hoặc các công cụ monitoring chuyên nghiệp."*
Sử dụng `debugPrint` hoặc bọc trong `if (kDebugMode)` nếu thực sự cần in ra console lúc debug, còn lại đẩy lên Crashlytics ở production.

## 5. Nỗi Đau Junior (Junior Pitfalls) 🤦‍♂️
### ❌ Sai Lầm (Code Bốc Mùi)
Junior thường dùng `try-catch` nhưng sau đó "nuốt" luôn lỗi (swallow exception), khiến app tuy không văng nhưng chạy sai bét và chả ai biết vì sao.
```dart
try {
  await fetchUserData();
} catch (e) {
  print('Lỗi rồi: $e'); // ❌ Nuốt lỗi, Crashlytics không hề hay biết!
}
```

### ✅ Đúng (Code Senior)
```dart
try {
  await fetchUserData();
} catch (e, stackTrace) {
  // Ghi nhận lỗi nhưng không làm crash app (non-fatal)
  FirebaseCrashlytics.instance.recordError(e, stackTrace, reason: 'Lỗi khi fetchUserData');
  // Hiện UI thông báo cho user (nếu cần)
}
```

## 6. 🐛 Thử Thách Gỡ Lỗi (Debugging Challenge)
Đoạn code sau đây dùng để log sự kiện khi user mua hàng, nhưng Firebase Analytics lại chả nhận được data gì:
```dart
void logPurchase(String itemId) {
  FirebaseAnalytics.instance.logEvent(
    name: 'purchase event', // Cố tình viết sai quy tắc
    parameters: {'Item_ID': itemId},
  );
}
```
**Nhiệm vụ của bạn**: Chạy thử và sửa lại cho đúng. 
*Gợi ý*: Analytics có quy định rất nghiêm ngặt về độ dài và định dạng của tên event/parameter (không có khoảng trắng, dùng chữ thường và dấu gạch dưới).

## 7. 🚀 Mini Pet Project
**Hệ thống Log Sự Kiện Mua Sắm**
Tạo một app bán hàng nhỏ:
1. Gắn Firebase Analytics để track sự kiện `view_item` khi vào màn hình chi tiết sản phẩm, và `add_to_cart` khi bấm nút.
2. Cố tình tạo ra một nút bấm "Gây Lỗi" (Throw exception) để xem nó hiển thị thế nào trên Crashlytics Dashboard.
3. Thiết lập custom keys trong Crashlytics (VD: `FirebaseCrashlytics.instance.setCustomKey('user_role', 'premium_member')`) trước khi crash để xem context lỗi trên dashboard!
