# Kiến thức nền tảng: JNI (Android) & Objective-C (iOS) 📚🛠️

## 1. Mở Đầu (Tại sao lập trình viên Flutter cần biết cái này?)
Bạn có thể code giao diện Flutter cực bay bổng, nhưng đến một ngày sếp yêu cầu: "Tích hợp SDK máy quét vân tay của hãng X vào app đi em". Xui thay, SDK đó chỉ có file `.aar` (Android) viết bằng C/C++ (JNI) và `.framework` (iOS) viết bằng Objective-C.
Hiểu nền tảng hệ điều hành giúp bạn:
- Đọc hiểu tài liệu native.
- Tự viết Plugin hoặc MethodChannel thành thạo thay vì đi ăn xin code trên StackOverflow.

## 2. Nền tảng Android & JNI (Java Native Interface)
HĐH Android chạy trên máy ảo ART (trước đây là Dalvik). Các app thường viết bằng Java/Kotlin.
Nhưng nếu bạn cần hiệu năng cao (game, xử lý ảnh), bạn phải code bằng C/C++.
**JNI** là cầu nối cho phép code Java gọi code C/C++ và ngược lại.

Khi Flutter chạy trên Android, engine lõi của nó được viết bằng C++, sau đó dùng JNI để nói chuyện với lớp Java/Kotlin để lấy thông tin hệ thống (như % pin, Bluetooth). Khi bạn gọi MethodChannel, luồng đi sẽ là: `Dart -> C++ (Flutter Engine) -> JNI -> Java/Kotlin`.

## 3. Nền tảng iOS & Objective-C / Swift
iOS không có JNI vì nó không chạy trên máy ảo Java. iOS được compile trực tiếp ra mã máy.
- **Objective-C (Obj-C)**: Ngôn ngữ cổ đại của Apple, cú pháp cực kỳ "dị" (dùng ngoặc vuông `[ ]` để gọi hàm). Rất nhiều core framework và library cũ (thậm chí Flutter engine) vẫn dùng nó.
- **Swift**: Ngôn ngữ mới, xịn xò, dễ học, cú pháp giống Kotlin/Dart.

Khi giao tiếp MethodChannel trên iOS: `Dart -> C++ (Flutter Engine) -> Objective-C/Swift`.

## 4. Senior Detail & Fun Fact 🧠
- **Senior Detail**: Trên iOS, khi code Swift để làm Plugin, bạn phải export header qua một cái cầu nối gọi là `Bridging-Header.h` thì Objective-C (của Flutter engine) mới hiểu được.
- **Fun Fact**: Cú pháp của Objective-C dị đến mức nhiều dev thà nghỉ việc chứ không chịu maintain app Obj-C. Ví dụ gọi hàm: `[myObject doSomethingWith: param1 and: param2];`. Tuy nhiên, vì C và C++ có thể nhúng trực tiếp vào Obj-C (gọi là Objective-C++ `.mm`), việc viết FFI cho iOS lại DỄ hơn Android cực nhiều!

## 5. Nỗi Đau Junior (Junior Pitfalls) 🤦‍♂️
### ❌ Sai Lầm (Code Bốc Mùi)
Junior thường sợ và né tránh việc mở XCode hay Android Studio. Cứ lỗi build là xóa folder `ios` và `android` rồi chạy `flutter create .` lại từ đầu. Thói quen này cực kỳ độc hại và sẽ phá nát các cấu hình native (như custom `Info.plist` hay `AndroidManifest.xml`).

### ✅ Đúng (Code Senior)
Mạnh dạn mở thư mục `android` bằng Android Studio và thư mục `ios` bằng XCode. Học cách đọc log lỗi bằng Logcat và XCode Console thay vì chỉ nhìn vào terminal của Flutter.

## 6. 🐛 Thử Thách Gỡ Lỗi (Debugging Challenge)
Bạn đưa một thư viện C++ vào app Flutter qua FFI. Chạy trên máy ảo (Simulator) iOS thì ngon lành, build ra máy thật (iPhone) thì crash cái đùng và báo lỗi **"Undefined symbols for architecture arm64"**.
**Nhiệm vụ của bạn**: Tại sao?
*Gợi ý*: Máy ảo Mac chạy chip Intel/M1 x86_64/arm64, còn iPhone thật chạy chip arm64. File thư viện `.a` hoặc `.so` của bạn đã được build cho kiến trúc nào?

## 7. 🚀 Mini Pet Project
**Hello World C/C++ qua FFI**
1. Tạo 1 file `hello.c` đơn giản chứa hàm `int add(int a, int b) { return a + b; }`.
2. Mở `android/CMakeLists.txt` và `ios/Runner.xcodeproj`, link file C đó vào.
3. Bên Dart, dùng package `dart:ffi` để load hàm `add` và gọi thử `print(add(5, 10))`.
4. Nếu màn hình in ra 15, chúc mừng, bạn đã chạm một tay vào cảnh giới Senior Native Interop!
