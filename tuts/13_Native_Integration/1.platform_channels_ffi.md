# Giao tiếp với Native (Platform Channels & FFI): Từ Newbie đến Senior 🌉🔌

## 1. Mở Đầu (Tại sao phải dính tới Native?)
Flutter không thể làm được mọi thứ. Đôi khi bạn cần:
- Lấy % pin của điện thoại (không có package nào đáp ứng ý bạn).
- Chạy một thư viện C/C++ cực nhanh (như OpenCV xử lý ảnh).
- Gọi một SDK mua hàng của VNPay hoặc ZaloPay vốn chỉ viết bằng Java/Kotlin/Swift.

Đó là lúc chúng ta dùng:
- **MethodChannel**: Để Dart gọi Kotlin/Swift.
- **FFI (Foreign Function Interface)**: Để Dart gọi trực tiếp C/C++ với tốc độ bàn thờ.

## 2. Setup Cơ Bản với MethodChannel (Newbie)
Ví dụ: Lấy % Pin của Android.

**Bên Dart:**
```dart
import 'package:flutter/services.dart';

class BatteryLevel {
  static const platform = MethodChannel('samples.flutter.dev/battery');

  static Future<String> getBatteryLevel() async {
    try {
      final int result = await platform.invokeMethod('getBatteryLevel');
      return 'Battery level is $result % .';
    } on PlatformException catch (e) {
      return "Failed to get battery level: '${e.message}'.";
    }
  }
}
```

**Bên Android (Kotlin - `MainActivity.kt`):**
```kotlin
import androidx.annotation.NonNull
import io.flutter.embedding.android.FlutterActivity
import io.flutter.embedding.engine.FlutterEngine
import io.flutter.plugin.common.MethodChannel

class MainActivity: FlutterActivity() {
  private val CHANNEL = "samples.flutter.dev/battery"

  override fun configureFlutterEngine(@NonNull flutterEngine: FlutterEngine) {
    super.configureFlutterEngine(flutterEngine)
    MethodChannel(flutterEngine.dartExecutor.binaryMessenger, CHANNEL).setMethodCallHandler {
      call, result ->
      if (call.method == "getBatteryLevel") {
        val batteryLevel = 85 // Giả lập lấy pin 85%
        result.success(batteryLevel)
      } else {
        result.notImplemented()
      }
    }
  }
}
```

## 3. Senior Detail & Fun Fact 🧠
- **Senior Detail**: Giao tiếp qua `MethodChannel` là bất đồng bộ và tốn chi phí (overhead) serialize/deserialize data sang JSON/Binary. Nếu gọi MethodChannel 1000 lần/giây, app sẽ lag tung chảo. Nếu cần gọi liên tục (render video, AI), phải dùng **FFI**!
- **Fun Fact**: Từ Flutter 3.x, bạn có thể dùng `Pigeon` (một package của Google) để generate ra code giao tiếp Type-Safe giữa Dart và Native, thay vì gửi string `"getBatteryLevel"` rủi ro gõ sai chính tả.

## 4. Google Style Guide Advice 📐
> *"Khi đặt tên MethodChannel, hãy sử dụng quy tắc domain-reverse để tránh xung đột với các plugin khác. VD: `com.yourcompany.app/feature`."*

## 5. Nỗi Đau Junior (Junior Pitfalls) 🤦‍♂️
### ❌ Sai Lầm (Code Bốc Mùi)
Quên bắt ngoại lệ (Exception) khi gọi sang Native. Nếu bên Native bị crash hoặc không implement hàm đó, toàn bộ màn hình Flutter sẽ bị trắng xóa hoặc văng lỗi đỏ lòm.
```dart
// ❌ Ngây thơ nghĩ rằng Native luôn trả về kết quả
final result = await platform.invokeMethod('doSomething');
```

### ✅ Đúng (Code Senior)
```dart
// ✅ Luôn bọc Try-Catch PlatformException
try {
  final result = await platform.invokeMethod('doSomething');
} on PlatformException catch (e) {
  print("Native error: ${e.code} - ${e.message}");
} on MissingPluginException catch (e) {
  print("Hàm này chưa được code bên Native!");
}
```

## 6. 🐛 Thử Thách Gỡ Lỗi (Debugging Challenge)
Bạn gọi hàm `platform.invokeMethod('getData')` và nhận được lỗi **`MissingPluginException`**.
Bạn mở file `MainActivity.kt` ra kiểm tra thì hàm `"getData"` CÓ TỒN TẠI ở đó. 
**Nhiệm vụ của bạn**: Tại sao lại có lỗi này? Làm sao để fix?
*Gợi ý*: Chuyện gì xảy ra nếu bạn vừa viết thêm code Native nhưng lại nhấn Hot Reload/Hot Restart thay vì nhấn nút **Stop** và **Build lại** app từ đầu?

## 7. 🚀 Mini Pet Project
**App Giao Tiếp Đa Nền Tảng (Pigeon)**
1. Tải package `pigeon`.
2. Tạo 1 file `message.dart` định nghĩa một interface `HostApi` có hàm `String getDeviceInfo()`.
3. Chạy lệnh generate của Pigeon để nó tự tạo ra file Java/Kotlin và Objective-C/Swift.
4. Implement interface đó bên Android và iOS (trả về tên dòng máy).
5. Gọi hàm đó từ Flutter UI. Trải nghiệm sự tuyệt vời của việc code Native có Auto-complete và báo lỗi Type-safe!
