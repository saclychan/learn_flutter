# Bài 1: Phá vỡ Ranh Giới với Platform Channels (Method Channels & FFI)

Có những lúc bạn tìm đỏ con mắt trên `pub.dev` mà không có package nào hỗ trợ tích hợp máy in mã vạch của tàu, hay thư viện xử lý ảnh siêu tốc bằng C++. Đây là lúc bạn phải cởi bỏ bộ đồ mượt mà của Flutter ra, và mặc vào chiếc áo giáp gai góc của Native Developer.

> 💡 **Fun Fact:** Flutter vẽ toàn bộ giao diện bằng Engine đồ họa riêng (Skia/Impeller) chứ không dùng nút bấm native của iOS/Android. Nghĩa là code Dart của bạn hoàn toàn cô lập. Để nói chuyện được với Java/Kotlin/Swift, Flutter dùng một "Đường ống đưa thư" tên là Platform Channel.

## 1. Method Channels (Sứ giả truyền tin)
Cách hoạt động giống hệt một API Client-Server. Flutter (Client) gửi yêu cầu "Lấy giùm tao phần trăm pin", Android/iOS (Server) xử lý và trả về "90%".

**Bên Flutter (Dart):**
```dart
const platform = MethodChannel('com.my_app/battery');

Future<void> getBatteryLevel() async {
  try {
    // Gọi phương thức tên là 'getBatteryLevel' xuống Native
    final int result = await platform.invokeMethod('getBatteryLevel');
    print('Pin đang là $result %');
  } on PlatformException catch (e) {
    print("Lỗi từ Native: '${e.message}'.");
  }
}
```

**Bên Android (Kotlin - MainActivity.kt):**
```kotlin
MethodChannel(flutterEngine.dartExecutor.binaryMessenger, "com.my_app/battery").setMethodCallHandler {
  call, result ->
  if (call.method == "getBatteryLevel") {
    val batteryLevel = getBatteryLevel() // Hàm native lấy pin
    if (batteryLevel != -1) {
      result.success(batteryLevel) // Trả kết quả lên Flutter
    } else {
      result.error("UNAVAILABLE", "Lỗi phần cứng", null)
    }
  } else {
    result.notImplemented()
  }
}
```

> 🧠 **Senior Detail:** Method Channel truyền tin bằng cách mã hóa dữ liệu thành byte (Serialization/Deserialization) rồi gửi qua lại. Việc này CỰC KỲ CHẬM nếu bạn truyền một bức ảnh 4K hoặc mảng 1 triệu phần tử (Sẽ gây nghẽn cổ chai và giật UI). Đừng bao giờ truyền dữ liệu lớn qua Method Channel!

## 2. FFI (Foreign Function Interface) - Tốc độ ánh sáng
Để giải bài toán truyền dữ liệu lớn và chạy thuật toán tốc độ cao, Dart cung cấp FFI (Dart FFI).
FFI cho phép code Dart gọi TRỰC TIẾP các hàm C/C++ (hoặc Rust) chung một vùng nhớ (Memory) mà không cần đóng gói dữ liệu gửi qua đường ống nào cả! Tốc độ của nó là tuyệt đối.

Nếu bạn cần viết app xử lý Video, Render 3D, hay AI cục bộ trên máy, FFI + C++ là con đường duy nhất.

## 🛑 Những nỗi đau và ngộ nhận khi còn Junior
- **Mù tịt Native:** Junior hễ nghe tới mở Xcode hay Android Studio là sợ toát mồ hôi. **Cách phòng tránh:** Một Senior Flutter không được phép sợ Native. Bạn không cần phải giỏi Swift/Kotlin để viết app, nhưng bạn BẮT BUỘC phải đọc hiểu được code của chúng để cấu hình, xin quyền, giải quyết xung đột Gradle/Cocoapods.
- **Dùng sai vũ khí:** Dùng Method Channel để đẩy một bức ảnh 10MB sang bên Native xử lý màu sắc. Chờ 3 giây để Flutter nén bức ảnh, 3 giây nữa Native giải nén. **Cách phòng tránh:** Chuyển đường dẫn (địa chỉ Path file) qua Channel. Bên Native nhận cái Path rồi tự mở file ảnh đó từ ổ cứng!

### 🚀 Mini Pet Project: Kẻ Gọi Hồn Native (Method Channel)

**Yêu cầu:**
1. Khởi tạo một project Flutter trắng.
2. Dùng đoạn code Dart ở phần 1 để tạo 1 cái nút "Lấy Pin".
3. Mở thư mục `android/app/src/main/kotlin/.../MainActivity.kt`. 
4. Code đè đoạn Kotlin phía trên vào (Bạn có thể lên trang chủ Flutter copy hàm getBatteryLevel thực sự của Android cho chính xác).
5. (Thử thách khó) Mở thư mục `ios/Runner/AppDelegate.swift` và viết đoạn code Swift tương đương để lấy Pin trên iPhone.
6. Build app chạy trên máy thật, bấm nút và cảm nhận việc code Dart của bạn vừa "sai khiến" hệ điều hành làm việc!
