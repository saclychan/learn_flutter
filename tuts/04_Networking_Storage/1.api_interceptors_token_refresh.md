# 1. API Interceptors & Token Refresh

Chào mừng bạn đến với module Networking! Khi làm app thực tế, gọi API bằng `http` đơn thuần là chưa đủ. Bạn phải biết cách cấu hình Interceptors (đánh chặn request/response) và xử lý luồng Token Refresh (khi Access Token hết hạn).

## 🌟 1. Từ Newbie: Interceptor là gì?

Thử tưởng tượng bạn có 50 API cần gọi. Ở API nào bạn cũng phải viết code: thêm `Authorization: Bearer <token>` vào header, rồi kiểm tra nếu mã lỗi `401` thì in ra log. Quá lặp lại!
**Interceptor** giống như một trạm thu phí. Mọi Request trước khi đi ra ngoài, và mọi Response trước khi về app, đều PHẢI đi qua trạm này. Thêm token? Đặt ở trạm thu phí! In log? Đặt ở trạm thu phí!

Thư viện phổ biến nhất Flutter cho việc này là **Dio**.

## 🧠 2. Tới Senior: Cơ chế Token Refresh Vô Hình (Seamless)

**Nỗi đau Token Hết Hạn:**
Access Token thường chỉ sống vài phút hoặc vài giờ để bảo mật. Khi nó hết hạn, API sẽ trả về `401 Unauthorized`.
**Senior xử lý thế nào?**
Thay vì đẩy người dùng ra màn hình Đăng nhập (bad UX), Senior sẽ dùng Refresh Token (sống lâu hơn) để âm thầm xin lại Access Token mới, rồi **gọi lại tự động** cái Request vừa bị fail. Người dùng không hề hay biết!

## 💡 Lời khuyên từ Google / Dart Style Guide

> **Do** use structured error handling and avoid leaking implementation details.
Khi xử lý lỗi mạng, hãy chuyển đổi các mã lỗi HTTP thành các Custom Exception (ví dụ: `NetworkException`, `UnauthorizedException`) thay vì để UI phải check `if (statusCode == 401)`.

## 🤕 Nỗi đau Junior (Junior Pitfalls)

❌ **SAI (Cộng dồn lặp lại code khắp nơi):**
```dart
Future<void> getUser() async {
  final token = await prefs.getString('token');
  final response = await http.get(Uri.parse('/user'), headers: {
    'Authorization': 'Bearer $token'
  });
  if (response.statusCode == 401) {
    // Gọi hàm logout bằng tay khắp mọi nơi
    logout();
  }
}
```

✅ **ĐÚNG (Gom vào Dio Interceptor):**
```dart
dio.interceptors.add(InterceptorsWrapper(
  onRequest: (options, handler) async {
    options.headers["Authorization"] = "Bearer ${getToken()}";
    return handler.next(options);
  },
  onError: (DioError e, handler) async {
    if (e.response?.statusCode == 401) {
      // 1. Dùng Refresh Token lấy Access Token mới
      // 2. Gọi lại API vừa fail
      // 3. Trả về kết quả mới
      return handler.resolve(await retry(e.requestOptions));
    }
    return handler.next(e);
  },
));
```

## 🐛 Thử Thách Gỡ Lỗi (Intentional Bugs)

Đoạn mã Token Refresh sau sẽ gây ra lỗi nghiêm trọng nếu có 3 API bị 401 cùng một lúc. Lỗi gì?

```dart
onError: (DioError e, handler) async {
  if (e.response?.statusCode == 401) {
    // Gây lỗi khi nhiều request fail cùng lúc 👇
    final newToken = await api.refreshToken(); 
    saveToken(newToken);
    return handler.resolve(await dio.fetch(e.requestOptions));
  }
}
```
**Đáp án:** Lỗi **Race Condition**. Nếu có 3 request cùng chết vì 401, chúng sẽ kích hoạt hàm `refreshToken()` 3 LẦN song song. Hậu quả là token loạn cào cào, server trả về lỗi.
**Cách fix:** Phải có một biến cờ (flag) kiểu `isRefreshing = true` hoặc dùng `Completer` để block các request khác lại, chờ thằng đầu tiên lấy được token xong thì các thằng sau xài ké!
