# 4. WebSockets & Real-time Communication

App của bạn đã gọi API REST ngon lành, nhưng sếp bắt làm tính năng "Chat" hoặc "Bản đồ xe chạy real-time". REST API `GET` liên tục mỗi giây (Polling) sẽ nướng sạch pin và sập server. Đã tới lúc xài WebSockets.

## 🌟 1. Từ Newbie: WebSocket khác REST thế nào?

REST là kiểu "gọi dạ bảo vâng": App hỏi (Request), Server đáp (Response), xong đường ai nấy đi.
WebSocket là gọi điện thoại: Kết nối mở xuyên suốt, Server có thể chủ động "hét" vào mặt App bất cứ lúc nào (Push), và App cũng có thể gửi lên liên tục mà không cần thiết lập lại kết nối.

## 🧠 2. Tới Senior: Bền bỉ (Resilience) và Quản lý Stream

**Vấn đề rớt mạng (Reconnection):**
Khi dùng WebSocket, rớt mạng là chuyện như cơm bữa (người dùng đi vào thang máy).
Junior: Rớt mạng thì kệ, WebSocket văng Exception xong tịt ngòi.
Senior: Viết cơ chế Ping/Pong để check trạng thái kết nối. Nếu rớt, tự động reconnect bằng cấp số nhân thời gian (Exponential Backoff - thử lại sau 1s, 2s, 4s, 8s để tránh ddos server lúc có mạng lại).

**Quản lý Stream:**
Dữ liệu WebSocket trả về dưới dạng `Stream` trong Dart. Senior dùng `StreamBuilder` cực kỳ cẩn thận để tránh memory leak.

## 💡 Lời khuyên từ Google / Dart Style Guide

> **Do** close your Streams and Sinks.
Khi thoát màn hình, bắt buộc phải `.close()` WebSocket channel và `.cancel()` các StreamSubscription, nếu không app sẽ leak memory trầm trọng.

## 🤕 Nỗi đau Junior (Junior Pitfalls)

❌ **SAI (Cập nhật UI lặp lại quá nhiều bằng setState với Stream):**
```dart
channel.stream.listen((data) {
  // Nếu 1 giây có 100 tin nhắn, hàm build sẽ bị gọi 100 lần! Giật lag tung người!
  setState(() {
    chatList.add(data);
  });
});
```

✅ **ĐÚNG (Dùng StreamBuilder hoặc State Management chuẩn):**
```dart
// UI chỉ cần lắng nghe Stream
StreamBuilder(
  stream: channel.stream,
  builder: (context, snapshot) {
    if (snapshot.hasData) {
      return Text(snapshot.data.toString());
    }
    return CircularProgressIndicator();
  },
)
```
Hoặc lưu vào Local DB rồi để UI lắng nghe sự thay đổi của DB (Single Source of Truth).

## 🐛 Thử Thách Gỡ Lỗi (Intentional Bugs)

Tại sao sau khi vào màn hình Chat rồi thoát ra vài lần, tin nhắn bị nhảy đúp, lặp lại nhiều lần?

```dart
class _ChatState extends State<ChatScreen> {
  late StreamSubscription _sub;

  @override
  void initState() {
    super.initState();
    // LỖI: Lắng nghe nhưng quên hủy 👇
    _sub = chatService.messageStream.listen((msg) {
      print("Nhận tin nhắn: $msg");
    });
  }
}
```
**Đáp án:** Quên gọi `_sub.cancel()` trong hàm `dispose()`. Mỗi lần vào màn hình, bạn tạo thêm 1 Subscription mới. Vào 5 lần, 1 tin nhắn tới sẽ trigger hàm in ra 5 lần!
**Cách fix:**
```dart
@override
void dispose() {
  _sub.cancel();
  super.dispose();
}
```
