# Bài 2: Dependency Injection (DI) - Tiêm Phụ Thuộc

Dependency Injection (DI) nghe có vẻ đáng sợ, nhưng thực chất nó là cách giải quyết nguyên tắc chữ **D** (Dependency Inversion) trong SOLID. Hiểu đơn giản: **Đừng tự mua đồ, hãy nhờ người khác mang đồ đến cho bạn.**

> 💡 **Fun Fact:** Trong hệ sinh thái Flutter, `get_it` là thư viện Service Locator phổ biến nhất thế giới để thực hiện DI. Nó cho phép bạn lấy ra bất cứ object nào từ bất cứ đâu trong App mà không cần tới `BuildContext` (như Provider).

## 1. Vấn đề không có DI (Lệ thuộc chặt chẽ)
Bạn đang viết một `LoginController`. Trong đó bạn cần lưu dữ liệu vào `SharedPreferences`.

❌ **Junior (Sai):** Khởi tạo trực tiếp class con ở bên trong class cha.
```dart
class LoginController {
  final LocalStorage storage = LocalStorage(); // Khởi tạo cứng! Lệ thuộc chặt!

  void login() {
    storage.saveToken("123");
  }
}
```
Lúc viết Unit Test, bạn không thể ép `LoginController` dùng một ổ cứng giả (Mock) được, vì nó đã bị "dính cứng" với ổ thật `LocalStorage`.

## 2. Giải pháp Dependency Injection (Truyền qua Constructor)
✅ **Senior (Đúng):** Khai báo biến, bắt buộc truyền qua Constructor.
```dart
class LoginController {
  final LocalStorage storage; // Không khởi tạo ở đây!

  // Tiêm (Inject) nó qua constructor
  LoginController({required this.storage}); 

  void login() {
    storage.saveToken("123");
  }
}
```
Bây giờ, khi chạy thật, bạn nhét ổ cứng thật vào. Khi viết Test, bạn nhét ổ cứng giả vào. Hoàn hảo!

## 3. Quản lý khổng lồ với `get_it`
Nếu có 100 lớp, việc bạn truyền tay (Prop drilling) qua từng constructor sẽ dài cả cây số. `get_it` là cái Hộp Thần Kỳ ở giữa App.

```dart
final getIt = GetIt.instance;

void setupDI() {
  // Đăng ký ổ cứng thật vào Hộp. Singleton nghĩa là chỉ tạo 1 lần và xài chung toàn app.
  getIt.registerSingleton<LocalStorage>(LocalStorage());
  
  // Đăng ký LoginController. Nó sẽ tự chui vào hộp để tìm cái LocalStorage!
  getIt.registerFactory<LoginController>(
    () => LoginController(storage: getIt<LocalStorage>()),
  );
}
```

Từ bất cứ đâu trong App, muốn xài `LoginController`, chỉ việc gọi:
```dart
final controller = getIt<LoginController>();
```

## 🛑 Những nỗi đau và ngộ nhận khi còn Junior
- **Truyền tham số qua 5 đời Widget:** Junior có cái token ở màn hình A, muốn chuyển tới màn hình E, thế là truyền nó qua biến constructor của B, C, D (Mặc dù B,C,D không thèm xài tới token đó). **Cách phòng tránh:** Dùng State Management (Riverpod/BLoC) hoặc DI (get_it) để lưu trữ và truy xuất toàn cục.
- **Dùng Singleton bừa bãi:** Ghi cái gì cũng `registerSingleton` dẫn tới RAM bị phình to vì object không bao giờ bị hủy. **Cách phòng tránh:** Hiểu rõ `registerSingleton` (Sống vĩnh viễn) và `registerFactory` (Gắn kết lúc gọi và tự chết đi). Màn hình hay ViewModel thì nên dùng Factory.

### 🚀 Mini Pet Project: Chuyên gia Giao Hàng (DI Master)

**Yêu cầu:**
1. Cài package `get_it`.
2. Tạo 1 file `di_setup.dart`, khai báo biến global `final getIt = GetIt.instance;` và hàm `setup()`.
3. Tạo class `DatabaseService` có hàm in ra chữ "Đang kết nối Database thật".
4. Đăng ký `DatabaseService` vào `get_it` dưới dạng Singleton.
5. Ở file UI `main.dart`, trong hàm `main()`, hãy gọi hàm `setup()` đầu tiên. 
6. Trong Widget, lấy cái `DatabaseService` ra bằng lệnh `getIt<DatabaseService>()` và gọi hàm in chữ của nó khi bấm nút.
