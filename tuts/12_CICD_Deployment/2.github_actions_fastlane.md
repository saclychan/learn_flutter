# Bài 2: Tự động hóa CI/CD với GitHub Actions & Fastlane

Build một file APK cho Android mất 5 phút. Build file IPA bằng Xcode quạt tản nhiệt kêu vù vù mất 10 phút. Đẩy lên Apple TestFlight mất thêm 15 phút rớt mạng. Một ngày gửi bản Test cho QA 3 lần là mất tong 1.5 tiếng cuộc đời.

Sứ mệnh của DevOps/Senior là: **"Việc lặp đi lặp lại của con người phải để cho máy móc làm."** Đó là CI/CD (Continuous Integration / Continuous Deployment).

> 💡 **Fun Fact:** CI/CD không có phép màu. Nó đơn giản là thuê một con máy tính (Server) xịn xò của GitHub hoặc GitLab, bảo nó "Lấy code của tao về, chạy lệnh Build giùm tao, xong ném cái file lên Store giùm luôn!".

## 1. CI (Continuous Integration): Tích hợp liên tục
Mục tiêu của CI là Đảm Bảo Chất Lượng Code.
Khi có 1 Junior mở một cái Pull Request (Gộp code) lên nhánh `main`. GitHub Actions sẽ chặn lại và tự động kích hoạt kịch bản CI:
- **Linting:** Chạy `flutter analyze` để kiểm tra lỗi cú pháp, biến thừa.
- **Testing:** Chạy `flutter test` để tự động kích hoạt toàn bộ Unit Test.
Nếu cả 2 lệnh trên màu Xanh (Pass), thì nút "Merge" mới sáng lên cho gộp code. Ai code ẩu làm gãy Unit Test -> Máy chủ đánh Fail, từ chối nhận code!

```yaml
# Ví dụ file .github/workflows/ci.yml
name: Flutter CI
on:
  pull_request:
    branches: [ main ]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v3
    - uses: subosito/flutter-action@v2
    - run: flutter pub get
    - run: flutter analyze
    - run: flutter test
```

## 2. CD (Continuous Deployment) với Fastlane
Nếu GitHub Actions lo phần chay lệnh, thì `Fastlane` (Công cụ quản lý App) lo việc tương tác với các Chợ Ứng Dụng (Store).

Thay vì phải tự lên giao diện web App Store Connect điền Version 1.0.2, điền Changelog, tải file IPA lên. Fastlane cung cấp 1 đoạn kịch bản (Ruby):
```ruby
# fastlane/Fastfile
lane :deploy_testflight do
  build_app(workspace: "Runner.xcworkspace", scheme: "Runner")
  upload_to_testflight
end
```
Giờ đây, bạn chỉ gõ 1 lệnh `fastlane deploy_testflight` và đi pha cà phê. Máy tính sẽ tự động ký Chứng chỉ (Certificates), Build, nén, và đẩy thẳng lên máy Tester.

> 🧠 **Senior Detail:** Cấu hình CD cho iOS rất cực vì hệ thống Certificate và Provisioning Profile của Apple siêu phức tạp. Giới Senior dùng tính năng `match` của Fastlane để tự động sinh và đồng bộ Certificate qua Github riêng tư, chấm dứt hoàn toàn cơn ác mộng "Code build được trên máy anh mà lỗi trên máy em".

## 🛑 Những nỗi đau và ngộ nhận khi còn Junior
- **Build bằng máy cá nhân và khóc:** File cấu hình JKS (Android Key) hoặc P12 (iOS Cert) nằm rải rác trên máy tính nhân viên. Nhân viên nghỉ việc, công ty KHÔNG THỂ CẬP NHẬT APP được nữa vì mất key chữ ký. **Cách phòng tránh:** Tách biệt hoàn toàn việc Build App ra khỏi máy cá nhân. Mọi thứ phải chạy trên Server CI/CD, key bảo mật phải lưu ở biến môi trường (Secrets) của GitHub.
- **Push code lên `main` bừa bãi:** Không có CI chặn cổng. Lỗi cú pháp push thẳng lên main làm toàn team pull về đều không chạy được app.

### 🚀 Mini Pet Project: Cảnh sát CI (GitHub Actions)

**Yêu cầu:**
1. Tạo một Repository mới trên GitHub (Private hay Public đều được). Push code Flutter của bạn lên nhánh `main`.
2. Tạo thư mục `.github/workflows` trong thư mục gốc.
3. Tạo file `flutter_ci.yml` và copy đoạn code YAML phần 1 vào.
4. Ở máy tính của bạn, cố tình làm hỏng code (Ví dụ: Thêm dấu phẩy lỗi cú pháp, hoặc viết một Unit test `expect(1, 2)` cố tình sai).
5. Push code lên (hoặc tạo Pull Request).
6. Mở trình duyệt, vào tab **Actions** trên GitHub. Chờ 2 phút. Bạn sẽ thấy máy chủ báo cái dấu ❌ Đỏ Chót! Bấm vào xem log báo lỗi dòng nào. Kỷ luật thép đã được thiết lập!
