# CI/CD với Github Actions & Fastlane: Từ Newbie đến Senior 🤖🚀

## 1. Mở Đầu
Mỗi lần release app, bạn phải:
1. Chạy Unit test.
2. Build file APK/AAB.
3. Mở web Google Play Console, upload, ghi release notes.
4. Lặp lại với iOS.
Mất nguyên 1 buổi sáng! **CI/CD (Continuous Integration / Continuous Deployment)** sinh ra để làm việc này tự động mỗi khi bạn push code lên Github.

## 2. Setup Cơ Bản với Github Actions (Newbie)
Tạo file `.github/workflows/flutter_build.yml` trong project:

```yaml
name: Flutter CI

on:
  push:
    branches: [ "main" ]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: subosito/flutter-action@v2
        with:
          flutter-version: '3.19.0'
      
      - run: flutter pub get
      - run: flutter test
      - run: flutter build apk --release
      
      - name: Upload APK
        uses: actions/upload-artifact@v3
        with:
          name: release-apk
          path: build/app/outputs/flutter-apk/app-release.apk
```
Đoạn code trên tự động cài Flutter, chạy test, build APK và đính kèm file APK vào Action mỗi khi bạn push lên nhánh `main`.

## 3. Senior Detail & Fun Fact 🧠
- **Senior Detail**: Đừng lưu Keystore password hay Google Play JSON Key trong source code. Hãy sử dụng **GitHub Secrets** (`${{ secrets.KEYSTORE_PASSWORD }}`) và lấy ra lúc chạy CI để decode file base64 của keystore.
- **Fun Fact**: GitHub Actions cung cấp máy MacOS (`runs-on: macos-latest`) miễn phí, nhưng nó trừ phút (minutes) nhanh gấp 10 lần máy Ubuntu! Nên hạn chế chạy build iOS trên Github trừ khi thật sự cần.

## 5. Nỗi Đau Junior (Junior Pitfalls) 🤦‍♂️
### ❌ Sai Lầm (Code Bốc Mùi)
Push thẳng file `key.properties` và `keystore.jks` chứa mật khẩu ký (sign) app lên GitHub Public Repository. 
-> Chúc mừng bạn, ai cũng có thể giả mạo app của bạn để đẩy lên Store!

### ✅ Đúng (Code Senior)
Encode file `.jks` ra Base64, lưu chuỗi đó vào GitHub Secrets. Lúc chạy GitHub action, tạo một step để decode nó lại thành file.
```yaml
      - name: Decode Keystore
        run: echo "${{ secrets.KEYSTORE_BASE64 }}" | base64 --decode > android/app/keystore.jks
```

## 6. 🐛 Thử Thách Gỡ Lỗi (Debugging Challenge)
Lệnh `flutter test` trong Github Action luôn bị **Fail**, mặc dù bạn chạy `flutter test` ở máy tính (Local) thì **Pass** 100%. 
Lỗi ghi trên log: `SocketException: Connection refused`.
**Nhiệm vụ của bạn**: Tìm hiểu tại sao? 
*Gợi ý*: Trên máy local, bạn đang cắm app vào Firebase Emulator hay chạy một Backend API cục bộ ở `localhost:8080`, nhưng trên máy chủ ảo của Github Actions thì backend đó đâu có chạy? Hãy học cách mock API trong khi test.

## 7. 🚀 System Design Challenge
**Hệ Thống Phân Phối App Tự Động (Fastlane)**
Hãy tích hợp `fastlane` vào dự án Flutter:
1. Viết một `Fastfile` bên trong thư mục `android/fastlane/`.
2. Tạo 1 lane tên là `beta`.
3. Lane này sẽ build AAB và tự động đẩy lên **Firebase App Distribution** để các Tester có thể tải về điện thoại ngay lập tức mà không cần qua Google Play.
4. Gọi lệnh `fastlane beta` này từ bên trong Github Actions.
