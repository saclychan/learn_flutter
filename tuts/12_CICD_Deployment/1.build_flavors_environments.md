# Bài 1: Môi trường Biến thể (Build Flavors / Environments)

Khi dự án to ra, bạn không thể code xong tính năng rồi dùng DB thật để test được. Lỡ tay gửi thông báo rác cho 1 triệu user thật thì ngày mai lên báo! Bạn cần chia dự án làm 3 môi trường: DEV (Code & Test nội bộ), STAGING (Beta cho Tester/Khách hàng), và PRODUCTION (Cho user thật xài).

> 💡 **Fun Fact:** Build Flavors thực ra là thuật ngữ của Android. Trong thế giới iOS, nó được gọi là Schemes & Build Configurations. Flutter cung cấp cơ chế `--flavor` để gộp 2 thế giới này lại một cách tương đối.

## 1. Tại sao phải phân tách Môi trường?
- **Khác API Url:** DEV gọi `dev.api.com`, PROD gọi `api.com`.
- **Khác Firebase:** Dữ liệu DEV không được dính dáng tới PROD.
- **Khác Tên App / Icon:** App DEV tên là `My App (Dev)` icon màu xanh. App PROD tên `My App` icon màu đỏ. Nhìn vào điện thoại biết ngay đang mở app nào.
- **Khác Bundle ID:** DEV là `com.company.app.dev`, PROD là `com.company.app`. Cài song song 2 app trên cùng 1 máy.

## 2. Cách thiết lập cơ bản bằng Flutter
Dùng package `envied` (bảo mật khóa) hoặc package `flutter_dotenv` để đọc các file `.env` (ví dụ: `.env.dev`, `.env.prod`).

Thay vì 1 file `main.dart`, Senior sẽ tạo 3 file:
- `main_dev.dart`
- `main_staging.dart`
- `main_prod.dart`

```dart
// main_dev.dart
void main() {
  AppConfig.setup(
    apiUrl: 'https://dev.api.com',
    environment: EnvType.dev,
  );
  runApp(MyApp());
}
```
Khi chạy máy ảo, gõ: `flutter run -t lib/main_dev.dart`

> 🧠 **Senior Detail:** Việc chia file `.dart` chỉ giải quyết được phần mềm phía Flutter. Để đổi tên App, Icon, và Bundle ID lúc tải lên Store, bạn BẮT BUỘC phải mò vào code Native (Gradle của Android và Xcode của iOS) để khai báo Flavor/Schemes. Việc này tốn hàng tiếng đồng hồ cấu hình. Thay vào đó, giới Senior sử dụng package `flutter_flavorizr` để nó tự động chọc ngoáy vào cấu trúc Native và sinh ra đủ Flavor cho bạn!

## 3. Quản lý Mật khẩu & API Keys (Secrets)
Không bao giờ được đẩy Hardcode (như `const API_KEY = "12345"`) lên GitHub. Hacker scan một phát là bạn mất tài khoản.
Hãy dùng file `.env`, thêm `.env` vào file `.gitignore` để không bao giờ push nó lên mạng. Trong Flutter, cài gói `flutter_dotenv` để nạp biến từ file `.env`.

## 🛑 Những nỗi đau và ngộ nhận khi còn Junior
- **Quên đổi API lúc lên Store:** Hardcode cái cục `dev.api.com` xong quên mất. Build ra Store xịn sò. Khách hàng xài toàn lấy data test của Dev. **Cách phòng tránh:** Khóa cứng biến cấu hình theo flavor. Lúc Build Release thì Build Server (CI/CD) sẽ TỰ ĐỘNG nạp file `.env.prod` vào. Lập trình viên không cần nhớ, không bao giờ sai!

### 🚀 Mini Pet Project: Đa nhân cách (Multi-Flavor Setup)

**Yêu cầu:**
1. Tạo 2 file: `.env.dev` chứa `APP_NAME="App DEV"` và `.env.prod` chứa `APP_NAME="App PROD"`.
2. Tạo 2 file `main_dev.dart` và `main_prod.dart`.
3. Sử dụng `flutter_dotenv` tải `.env` tương ứng.
4. Màn hình giữa in ra chữ to đùng `APP_NAME`.
5. Mở 2 cửa sổ terminal:
   - Cửa sổ 1 gõ: `flutter run -t lib/main_dev.dart -d chrome` -> Giao diện hiện chữ App DEV.
   - Cửa sổ 2 gõ: `flutter run -t lib/main_prod.dart -d chrome` -> Giao diện hiện chữ App PROD.
