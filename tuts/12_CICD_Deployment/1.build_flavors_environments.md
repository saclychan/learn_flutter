# Build Flavors & Environments: Từ Newbie đến Senior 🌍✨

## 1. Mở Đầu: Flavor là gì?
Tưởng tượng bạn có 1 app nhưng cần chia ra 3 phiên bản:
- **Dev**: Dành cho bạn test, gọi API server `api-dev.com`, icon app màu xanh rêu.
- **Staging**: Dành cho QA/Tester, gọi API server `api-staging.com`, icon màu vàng.
- **Production**: Dành cho User xịn, gọi API server `api-prod.com`, icon màu đỏ chuẩn chỉ.

Thay vì mỗi lần build lại phải copy-paste sửa code mệt mỏi, chúng ta dùng **Flavors** (bên Android) và **Schemes** (bên iOS).

## 2. Setup Cơ Bản (Newbie)
Trong Flutter, ta thường quản lý môi trường bằng biến khi chạy lệnh:
```bash
flutter run --flavor dev -t lib/main_dev.dart
```

Code Dart chia theo môi trường:
```dart
// lib/env.dart
enum Environment { dev, staging, prod }

class AppConfig {
  final Environment env;
  final String apiBaseUrl;

  AppConfig({required this.env, required this.apiBaseUrl});
}

// lib/main_dev.dart
void main() {
  var config = AppConfig(env: Environment.dev, apiBaseUrl: 'https://dev.api.com');
  runApp(MyApp(config: config));
}
```

## 3. Senior Detail & Fun Fact 🧠
- **Senior Detail**: Đừng nhét `apiBaseUrl` hay các token nhạy cảm cứng vào trong code (hardcode). Hãy kết hợp Flavors với `--dart-define` hoặc file `.env` (package `flutter_dotenv`) để bảo mật.
- **Fun Fact**: Trên Android, bạn sửa `app/build.gradle` (productFlavors). Trên iOS, bạn phải mở XCode, duplicate cấu hình (Debug/Release/Profile) thành Debug-dev, Release-dev, v.v. Rất đau đầu với iOS! Dùng package `flutter_flavorizr` để tự động hóa việc này.

## 4. Google Style Guide Advice 📐
> *"Các file cấu hình ứng dụng hoặc secret keys tuyệt đối không được commit lên source control (Git). Hãy sử dụng `.gitignore` và load chúng từ environment variables."*

## 5. Nỗi Đau Junior (Junior Pitfalls) 🤦‍♂️
### ❌ Sai Lầm (Code Bốc Mùi)
Hardcode môi trường bằng các biến global và sửa tay trước khi build. Quên sửa phát là build nhầm App Dev đưa lên Store luôn!
```dart
// ❌ Cứ mỗi lần build prod là phải vào comment dòng dev, mở dòng prod
const BASE_URL = "https://api-dev.com";
// const BASE_URL = "https://api-prod.com"; 
```

### ✅ Đúng (Code Senior)
Dùng `--dart-define` lúc chạy lệnh: `flutter run --dart-define=BASE_URL=https://api.com`
```dart
// ✅ Đọc trực tiếp từ lúc build, không bao giờ nhầm lẫn!
const baseUrl = String.fromEnvironment('BASE_URL', defaultValue: 'https://api-dev.com');
```

## 6. 🐛 Thử Thách Gỡ Lỗi (Debugging Challenge)
Bạn đã thêm đoạn code sau vào `build.gradle` của Android:
```gradle
flavorDimensions "env"
productFlavors {
    dev {
        dimension "env"
        applicationIdSuffix ".dev"
    }
    prod {
        dimension "env"
    }
}
```
Nhưng khi chạy `flutter run --flavor staging`, nó báo lỗi không tìm thấy flavor. 
**Nhiệm vụ của bạn**: Tại sao lại lỗi? Làm sao để sửa? (Gợi ý: Nhìn kỹ danh sách flavors trong gradle file).

## 7. 🚀 Mini Pet Project
**Cấu Hình Đa Vũ Trụ App**
1. Dùng package `flutter_flavorizr` để gen tự động 2 flavor: `dev` và `prod` cho cả Android và iOS.
2. Code Dart sao cho: 
   - Chạy flavor `dev`: AppBar hiện chữ "App Dev (API DEV)" nền đỏ.
   - Chạy flavor `prod`: AppBar hiện chữ "App Xịn" nền xanh.
3. Test chạy bằng 2 lệnh `flutter run --flavor dev -t lib/main_dev.dart` và `flutter run --flavor prod -t lib/main_prod.dart`.
