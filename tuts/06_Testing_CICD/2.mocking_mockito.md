# Mocking & Testing Trong Flutter: Bí Kíp Mockito

## 1. Giới thiệu: Tại sao không gọi API thật khi Unit Test?
Một sai lầm phổ biến khi viết test là bạn vẫn để code gọi đến Backend hoặc Database thực. Điều này biến Unit Test thành Integration Test. 
Nếu mạng chậm, test fail. Nếu data trên server đổi, test fail.
Đó là lúc ta cần **Mocking**. Mock là việc tạo ra một "bản sao" của các dependencies (như Repository, API Client) để giả lập hành vi mà không cần chạy code thực. `mockito` và `mocktail` là hai package phổ biến nhất.

**Senior Detail:** Ở thời đại Null Safety, `mockito` yêu cầu phải generate code (bằng build_runner) để tạo file `.mocks.dart`. Nếu bạn ghét việc sinh code, hãy thử `mocktail` - nó hoạt động tương tự mockito nhưng không cần build_runner!

---

## 2. Lời khuyên Google/Dart Style Guide
> "DO name test files after the file being tested, followed by `_test.dart`."
Nếu bạn test `user_repository.dart`, file test bắt buộc phải là `user_repository_test.dart`.
> "PREFER setting up mocks in `setUp` method."
Tránh khởi tạo lại Mock object ở mỗi test case, hãy gom chúng vào `setUp`.

## 3. Nỗi đau Junior: Code ❌ SAI và ✅ ĐÚNG

### Nỗi đau 1: Quên "Mock" mà truyền luôn object thật
**Ngộ nhận:** Newbie cố gắng truyền luôn đối tượng thật vào UseCase, rồi bị lỗi vì đối tượng đó đòi kết nối DB.

❌ **SAI (Junior Pitfall):**
```dart
void main() {
  test('Login logic', () async {
    // Truyền DB thật, chết dở!
    final repo = UserRepositoryImpl(http.Client()); 
    final useCase = LoginUseCase(repo);
    // ...
  });
}
```

✅ **ĐÚNG (Senior Way với Mockito):**
Sử dụng annotation `@GenerateMocks` và dùng bản mock.
```dart
import 'package:mockito/annotations.dart';
import 'package:mockito/mockito.dart';
import 'login_test.mocks.dart'; // File được generate

@GenerateMocks([UserRepository])
void main() {
  late MockUserRepository mockRepo;
  late LoginUseCase useCase;

  setUp(() {
    mockRepo = MockUserRepository();
    useCase = LoginUseCase(mockRepo);
  });

  test('Trả về true khi user > 18 tuổi', () async {
    // Giả lập hành vi của Mock
    when(mockRepo.getUser(any)).thenAnswer((_) async => User(age: 20));
    
    // Act
    final result = await useCase.execute('token');
    
    // Assert
    expect(result, true);
    verify(mockRepo.getUser('token')).called(1); // Kiểm tra hàm có được gọi đúng 1 lần không
  });
}
```

## 4. 🐛 Thử Thách Gỡ Lỗi (Debugging Challenge)

Đoạn test sử dụng `mockito` dưới đây bị ném ra một Exception `MissingStubError`. Bạn hãy tìm nguyên nhân!

```dart
test('Lưu thông tin user thành công', () async {
  final mockRepo = MockUserRepository();
  final useCase = SaveUserUseCase(mockRepo);
  
  // Hành động
  await useCase.execute(User(name: 'Alice'));
  
  // Kiểm tra
  verify(mockRepo.saveUser(any)).called(1);
});
```
**Gợi ý:** Trong Null Safety, nếu một hàm trả về `Future<void>` hoặc giá trị non-nullable, Mockito không thể tự đoán giá trị trả về mặc định. Bạn BẮT BUỘC phải "stub" (dùng `when().thenAnswer()`) cho mọi method được gọi, kể cả method trả về void. (Gợi ý thêm: xem xét cách dùng `when(...).thenAnswer((_) async => {});`)

## 5. 🚀 Mini Pet Project

**Yêu cầu:** 
1. Viết một hàm `WeatherService.getWeather(String city)` gọi HTTP thật.
2. Dùng `mockito` tạo `MockHttpClient`.
3. Viết Unit Test: 
   - Giả lập (when) API trả về JSON chứa nhiệt độ `25`. Verify hàm trả về đúng object `Weather(temp: 25)`.
   - Giả lập (when) HTTP ném ra Exception `404`, verify rằng `WeatherService` của bạn handle lỗi và quăng ra `WeatherNotFoundException`.
