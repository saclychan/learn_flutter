# Bài 2: Đỉnh cao Unit Test (Làm giả dữ liệu với Mockito)

Unit Test (Kiểm thử Đơn vị) bắt buộc code của bạn phải Tách Rời (Decoupled). Bạn không thể test hàm `login()` nếu hàm đó bắt buộc phải gọi API thật qua mạng wifi (Lỡ wifi rớt thì Test fail dù code không sai à?).

Đó là lý do chúng ta phải biết làm giả (Mock). Và `mockito` là vua làm giả trong hệ sinh thái Dart.

> 💡 **Fun Fact:** Mockito gốc là một thư viện của Java. Do Dart được thiết kế với tư duy rất gần Java/C#, Mockito bê nguyên bộ nguyên tắc đó sang Dart và hoạt động cực kỳ trơn tru (kết hợp với `build_runner`).

## 1. Mock (Làm giả) là gì?
Nếu class `AuthRepository` của bạn có hàm `loginAPI()`, thì khi viết Unit test cho màn hình Login, bạn sẽ tạo ra một cái `MockAuthRepository`.
Nó có hình dáng y hệt bản gốc, nhưng "ruột" rỗng. Bạn có thể BẮT ÉP nó phải trả về thành công hoặc thất bại mà không cần tới internet.

## 2. Cách dùng Mockito
Bạn bắt buộc phải cài 2 gói: `mockito` (cho production) và `build_runner` (cho quá trình sinh code mock).

```dart
// 1. Tạo file test, gắn Annotation tạo Mock cho cái Repository thật
@GenerateMocks([AuthRepository])
import 'login_test.mocks.dart'; // File này sẽ được sinh tự động

void main() {
  late MockAuthRepository mockRepo;

  setUp(() {
    mockRepo = MockAuthRepository(); // Khởi tạo đồ giả
  });

  test('Đăng nhập thành công trả về User', () async {
    // 2. STUBBING: ÉP (when) thằng đồ giả phải trả về (thenReturn) thứ mình muốn
    when(mockRepo.loginAPI('admin', '123'))
        .thenAnswer((_) async => User(id: 1, name: 'Admin'));

    // 3. Thực thi hành động cần Test
    final user = await mockRepo.loginAPI('admin', '123');

    // 4. Xác nhận (Assert)
    expect(user.name, 'Admin');
    
    // 5. Kiểm tra xem hàm loginAPI có THỰC SỰ ĐƯỢC GỌI không (Verify)
    verify(mockRepo.loginAPI('admin', '123')).called(1);
  });
}
```
Để cái file `login_test.mocks.dart` được tạo ra, bạn phải chạy lệnh: `dart run build_runner build`.

> 🧠 **Senior Detail:** Đừng lạm dụng Mocking! Có những thứ thuộc về Logic thuần túy (VD: Hàm tính tổng giỏ hàng, hàm kiểm tra regex Email) thì hãy test thẳng bằng class thật. Mock chỉ sinh ra để đối phó với những thứ đi ra ngoài biên giới của cái điện thoại (API, Database, File System, Hardware Sensor).

## 🛑 Những nỗi đau và ngộ nhận khi còn Junior
- **Không truyền Dependency (Lệ thuộc cứng):** Bạn nhét `final api = ApiClient();` thẳng vào ruột class. Tới lúc viết Test, bạn có cái Mock rồi mà KHÔNG CÁCH NÀO nhét cái Mock đó vào trong class để test được! **Cách phòng tránh:** Quay lại học ngay Bài Dependency Injection. Mọi thứ phải truyền qua Constructor thì mới truyền Mock vào thay thế được!
- **Sợ viết Test vì thấy lâu:** Junior kêu ca "Viết Test tốn gấp đôi thời gian code tính năng". Đúng! Nhưng khi App to lên, một sửa đổi nhỏ của bạn làm gãy 5 tính năng khác. Bạn sẽ mất 3 ngày đi tìm bug. Nếu có Test, nó sẽ báo đỏ cái tính năng bị gãy ngay trong 3 giây. Test là bảo hiểm sinh mạng cho Senior.

### 🚀 Mini Pet Project: Thử Thách Kẻ Mạo Danh

**Yêu cầu:**
1. Cài đặt package `test`, `mockito`, `build_runner`.
2. Tạo 1 class thật `WeatherApi` có hàm `Future<String> fetchWeather(String city)`. (Không cần code gọi HTTP thật, cứ ném đại chuỗi "Sunny" ra là được).
3. Tạo 1 class `WeatherCubit` (hoặc Controller) nhận `WeatherApi` qua constructor. Có hàm `getWeather(city)` gọi API và lưu vào biến.
4. Tạo file test `weather_test.dart`. Sử dụng `@GenerateMocks([WeatherApi])` và chạy `build_runner`.
5. Trong test, khởi tạo `WeatherCubit(mockApi)`. Dùng `when(...).thenAnswer((_) async => "Raining")`.
6. Gọi cubit.getWeather() và dùng `expect()` đảm bảo biến lưu trữ của Cubit đã chuyển thành "Raining". Cảm nhận sự uy lực của kẻ mạo danh!
