# 1. setState() Basics & Under The Hood

Chào mừng bạn đến với thế giới State Management trong Flutter! Ở bài này, chúng ta sẽ bắt đầu từ Newbie đến Senior với công cụ cơ bản nhất: `setState()`. Đừng khinh thường nó nhé, hiểu rõ `setState()` là nền tảng để bạn vươn tới các kiến trúc phức tạp hơn.

## 🌟 1. Từ Newbie: `setState()` là gì?

Khi bạn muốn thay đổi UI (ví dụ tăng số đếm, hiển thị loading), bạn cần cập nhật **State** (trạng thái) của widget. `setState()` là hàm báo cho Flutter biết: *"Này, dữ liệu của tôi đã thay đổi, hãy vẽ lại UI đi!"*

```dart
// Ví dụ kinh điển
int _counter = 0;

void _increment() {
  setState(() {
    _counter++;
  });
}
```

## 🧠 2. Tới Senior: `setState()` Under The Hood & Vấn đề O(N) Rebuilds

Bạn có bao giờ tự hỏi `setState()` thực sự làm gì không?
Khi bạn gọi `setState()`, Flutter không ngay lập tức vẽ lại màn hình. Nó đánh dấu Element tương ứng trong Element Tree là **"dirty"** (bằng cách gọi `markNeedsBuild()`). Ở frame tiếp theo, Flutter sẽ đi xuống cây widget từ điểm bị đánh dấu dirty và gọi hàm `build()` để tạo lại UI.

**Vấn đề O(N) Rebuilds:**
Nếu bạn đặt `setState()` ở gốc (root) của một cây widget rất lớn, Flutter sẽ phải chạy hàm `build()` của toàn bộ **N** widget con bên dưới nó. Mặc dù Flutter tối ưu hóa rất tốt, nhưng việc tạo lại các đối tượng Widget không cần thiết vẫn làm tốn CPU và gây giật lag (jank) nếu cây quá sâu và phức tạp.

**Quy tắc Vàng:** Hãy "đẩy" `setState()` xuống càng thấp (càng gần lá) trong cây widget càng tốt! (Push state down the tree).

## 💡 Lời khuyên từ Google / Dart Style Guide

> **Do** evaluate whether a widget needs to be a `StatefulWidget`. Use `StatelessWidget` when possible.
> **Do** keep the `build` method pure and avoid side effects. `build` should only return widgets.

## 🤕 Nỗi đau Junior (Junior Pitfalls)

Khi mới học, các bạn Junior thường ném mọi thứ vào một file và gọi `setState()` vô tội vạ. 

❌ **SAI (Cập nhật toàn bộ màn hình chỉ vì 1 cái nút):**
```dart
class BadScreen extends StatefulWidget {
  @override
  _BadScreenState createState() => _BadScreenState();
}
class _BadScreenState extends State<BadScreen> {
  bool _isLiked = false;

  @override
  Widget build(BuildContext context) {
    print("Rebuild toàn bộ màn hình to đùng!");
    return Scaffold(
      body: Column(
        children: [
          HeavyWidget1(), // Bị rebuild oan uổng
          HeavyWidget2(), // Bị rebuild oan uổng
          IconButton(
            icon: Icon(_isLiked ? Icons.favorite : Icons.favorite_border),
            onPressed: () {
              setState(() { _isLiked = !_isLiked; });
            },
          )
        ],
      ),
    );
  }
}
```

✅ **ĐÚNG (Tách widget nhỏ ra):**
```dart
class GoodScreen extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: Column(
        children: [
          HeavyWidget1(), // An toàn
          HeavyWidget2(), // An toàn
          LikeButton(), // Chỉ widget này rebuild
        ],
      ),
    );
  }
}

class LikeButton extends StatefulWidget {
  @override
  _LikeButtonState createState() => _LikeButtonState();
}
class _LikeButtonState extends State<LikeButton> {
  bool _isLiked = false;
  @override
  Widget build(BuildContext context) {
    return IconButton(
      icon: Icon(_isLiked ? Icons.favorite : Icons.favorite_border),
      onPressed: () { setState(() { _isLiked = !_isLiked; }); },
    );
  }
}
```

## 🐛 Thử Thách Gỡ Lỗi (Intentional Bugs)

Hãy tìm lỗi trong đoạn code sau và sửa nó. *Gợi ý: Lỗi xảy ra khi người dùng bấm nút fetch data rồi thoát màn hình trước khi data tải xong.*

```dart
class UserProfile extends StatefulWidget {
  @override
  _UserProfileState createState() => _UserProfileState();
}
class _UserProfileState extends State<UserProfile> {
  String name = "Loading...";

  void fetchUser() async {
    final result = await Future.delayed(Duration(seconds: 3), () => "John Doe");
    // LỖI TIỀM ẨN Ở ĐÂY 👇
    setState(() {
      name = result;
    });
  }
  
  @override
  void initState() {
    super.initState();
    fetchUser();
  }
  
  @override
  Widget build(BuildContext context) {
    return Text(name);
  }
}
```
**Đáp án:** Khi `await` kết thúc, widget có thể đã bị hủy (unmounted) do người dùng back ra ngoài. Gọi `setState()` lúc này sẽ gây lỗi runtime `setState() called after dispose()`.
**Cách fix:** Bọc `setState` trong `if (mounted) { ... }`.
