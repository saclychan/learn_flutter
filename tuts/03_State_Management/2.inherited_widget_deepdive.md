# 2. InheritedWidget Deep Dive - Nỗi Ám Ảnh Prop Drilling

Sau khi học `setState()`, bạn sẽ nhanh chóng nhận ra một vấn đề khi ứng dụng lớn lên: làm sao để truyền dữ liệu từ widget cha xuống tận cùng widget cháu chắt mà không phải truyền qua từng constructor (Prop Drilling)?

## 🌟 1. Từ Newbie: InheritedWidget là gì?

`InheritedWidget` là một widget đặc biệt trong Flutter cho phép các widget con bên dưới nó có thể truy cập dữ liệu của nó một cách trực tiếp, bỏ qua các widget trung gian.

Ví dụ kinh điển nhất mà bạn xài hằng ngày: `Theme.of(context)` hoặc `MediaQuery.of(context)`. Chúng đều là InheritedWidget!

## 🧠 2. Tới Senior: Cơ chế O(1) Lookup & Cạm bẫy O(N) Rebuilds

**Tại sao InheritedWidget lại nhanh (O(1) Lookup)?**
Mỗi `Element` trong Flutter duy trì một Map (từ điển) chứa các tham chiếu đến các InheritedWidget tổ tiên của nó. Khi bạn gọi `context.dependOnInheritedWidgetOfExactType<MyInherited>()`, Flutter chỉ cần tra cứu trong Map này với độ phức tạp O(1). Rất nhanh!

**Nhưng tại sao lại có cạm bẫy O(N) Rebuilds?**
Bên cạnh việc tra cứu, hàm `dependOnInheritedWidgetOfExactType` còn **đăng ký** widget hiện tại làm "người phụ thuộc" (dependent). Khi InheritedWidget thay đổi (hàm `updateShouldNotify` trả về true), nó sẽ duyệt qua danh sách các dependents và gọi `build()` của chúng.
Nếu bạn để InheritedWidget bọc quá cao và chứa dữ liệu thay đổi liên tục, bạn lại vướng vào bài toán O(N) rebuilds!

## 💡 Lời khuyên từ Google / Dart Style Guide

> **Consider** using established State Management libraries like Provider or Riverpod instead of writing raw `InheritedWidget` classes. 
Thực tế, Google khuyên bạn hiểu InheritedWidget để biết bản chất, nhưng trong dự án thực tế, viết boilerplate code cho nó rất mệt mỏi. Provider chính là một wrapper bọc quanh InheritedWidget!

## 🤕 Nỗi đau Junior (Junior Pitfalls)

❌ **SAI (Prop Drilling mỏi tay):**
```dart
class GrandParent extends StatelessWidget {
  final String userName = "John";
  @override
  Widget build(BuildContext context) => Parent(userName: userName);
}

class Parent extends StatelessWidget {
  final String userName;
  Parent({required this.userName});
  @override
  Widget build(BuildContext context) => Child(userName: userName); // Khổ thân Parent, ko dùng mà vẫn phải truyền
}
```

✅ **ĐÚNG (Sử dụng InheritedWidget hoặc Provider):**
Tạo một `UserInheritedWidget` bọc ngoài `GrandParent`, và ở `Child` chỉ cần gọi `UserInheritedWidget.of(context).userName`. Parent không cần quan tâm đến `userName` nữa.

## 🐛 Thử Thách Gỡ Lỗi (Intentional Bugs)

Đây là một InheritedWidget chứa biến đếm. Tại sao khi bấm nút, counter tăng nhưng giao diện không update?

```dart
class MyCounter extends InheritedWidget {
  int count = 0; // 🛑 LỖI KIẾN TRÚC Ở ĐÂY
  
  MyCounter({required Widget child}) : super(child: child);

  @override
  bool updateShouldNotify(MyCounter oldWidget) {
    return oldWidget.count != count;
  }
  
  static MyCounter of(BuildContext context) {
    return context.dependOnInheritedWidgetOfExactType<MyCounter>()!;
  }
}
```
**Đáp án:** `InheritedWidget` bản thân nó là **Immutable** (không thay đổi được, giống StatelessWidget). Bạn không thể thay đổi giá trị `count` trực tiếp và mong nó update UI. 
**Cách fix:** Bạn phải kết hợp nó với một `StatefulWidget` cha để nắm giữ State, mỗi khi `setState()` của cha được gọi, nó tạo ra một `InheritedWidget` mới với giá trị mới, từ đó trigger `updateShouldNotify`. Quá phức tạp đúng không? Đó là lý do Provider ra đời!
