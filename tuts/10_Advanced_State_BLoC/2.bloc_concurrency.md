# Bài 2: Concurrency trong BLoC (Kiểm soát Luồng Sự kiện)

Điểm ăn tiền lớn nhất của BLoC truyền thống (Event-Driven) so với Cubit hay Riverpod chính là tính năng **Concurrency (Kiểm soát luồng đồng thời)**. Nó cho phép bạn quản lý các sự kiện đến dồn dập (như user spam click nút) một cách cực kỳ tinh tế.

> 💡 **Fun Fact:** Trong phiên bản `bloc` cũ (trước v8.0), BLoC map các Event sang State bằng hàm `mapEventToState` (dựa hoàn toàn trên RxDart). Từ bản 8.0, cấu trúc đổi sang `on<Event>` dễ hiểu hơn, nhưng sức mạnh Concurrency (dùng package `bloc_concurrency`) thì vẫn khủng khiếp như ngày nào!

## 1. Vấn đề "Spam Click"
User bấm nút "Mua hàng". Gọi API mất 2 giây. Trong lúc đợi, user bấm lỳ thêm 10 lần nữa.
Nếu dùng `setState` hoặc `Cubit`, hàm mua hàng bị gọi 11 lần. Bạn trừ tiền user 11 lần! Đền ốm đòn.

## 2. Transformer thần thánh (`bloc_concurrency`)
Trong BLoC (không phải Cubit), khi đăng ký nhận 1 Event, bạn có thể ép luồng (Transformer) cho nó.

```dart
import 'package:bloc_concurrency/bloc_concurrency.dart';

class PaymentBloc extends Bloc<PaymentEvent, PaymentState> {
  PaymentBloc() : super(PaymentInitial()) {
    // on<Tên_Sự_Kiện> ( Hàm_Xử_Lý, transformer: Loại_Chặn_Luồng )
    
    // 1. Droppable: Đang xử lý sự kiện trước thì vứt bỏ (DROP) mọi sự kiện mới tới. (Chống Spam Click)
    on<PayButtonPressed>(_onPayPressed, transformer: droppable());
    
    // 2. Restartable: Hủy bỏ sự kiện cũ đang chạy dở, bắt đầu chạy sự kiện MỚI NHẤT. (Phù hợp cho ô Tìm kiếm)
    on<SearchQueryChanged>(_onSearch, transformer: restartable());
    
    // 3. Sequential: Xếp hàng. Xử lý xong cái 1 mới tới cái 2, cái 3.
    on<DownloadFile>(_onDownload, transformer: sequential());
    
    // 4. Concurrent (Mặc định): Chạy song song không cần biết ngày tháng.
  }

  Future<void> _onPayPressed(PayButtonPressed event, Emitter<PaymentState> emit) async {
    emit(PaymentLoading());
    await Future.delayed(Duration(seconds: 2)); // Giả lập API
    emit(PaymentSuccess());
  }
}
```

## 3. Ứng dụng thực tế: Live Search (Tìm kiếm trực tiếp)
Kết hợp `restartable()` của BLoC với `debounceTime` của rxdart, bạn tạo ra một thanh tìm kiếm chuẩn Shopee, Google:
1. Gõ chữ "a" -> Hủy. Gõ chữ "p" -> Hủy... Dừng gõ nửa giây -> Bắt đầu gọi API.
2. Gọi API tìm chữ "apple" mất 3 giây. Mới được 1 giây, User đổi ý gõ tiếp chữ "s".
3. Lập tức `restartable()` bóp nghẹt cái API cũ (hủy request cũ), gọi API mới với chữ "apples" ngay lập tức. Tối ưu Server đến tận răng!

## 🛑 Những nỗi đau và ngộ nhận khi còn Junior
- **Code cồng kềnh với Boolean Flags:** Junior dùng biến cờ `bool isLoading = false`. Vào hàm kiểm tra `if(isLoading) return`, chạy xong gán lại `isLoading = false` rồi dùng try/catch để đảm bảo không kẹt cờ. Quá thủ công và dễ lỗi! **Cách phòng tránh:** Dùng `transformer: droppable()` của BLoC. Code sạch không tì vết, không cần một biến cờ nào!
- **Dùng BLoC cho mọi thứ:** Thấy BLoC mạnh quá, cái gì cũng lôi BLoC ra xài kể cả cái nút bật tắt màu nền. Dẫn đến file đẻ ra như nấm (Cứ 1 tính năng sinh 3 file: bloc, event, state). **Cách phòng tránh:** Cái gì đơn giản thì xài Cubit. Chỉ khi nào dính tới Concurrency (Tìm kiếm, Gọi API chống spam, xử lý chuỗi sự kiện), mới rút thanh bảo kiếm BLoC ra!

### 🚀 Mini Pet Project: Thợ Săn Rác (Spam Blocker)

**Yêu cầu:**
1. Cài đặt 2 package: `flutter_bloc` và `bloc_concurrency`.
2. Định nghĩa một `SpamBloc` (Không xài Cubit nha). Có một sự kiện là `SpamEvent`.
3. Trong Bloc, dùng `on<SpamEvent>` với `transformer: droppable()`.
4. Logic xử lý: In ra "Đang xử lý...", sau đó `await Future.delayed(Duration(seconds: 3))`, in ra "Hoàn thành!".
5. Ở UI, tạo 1 nút bấm `add(SpamEvent())`.
6. Bấm nút như một cái máy khâu (Spam click 20 lần). 
7. Nhìn Console, nếu nó chỉ in "Đang xử lý..." ĐÚNG 1 LẦN và phớt lờ toàn bộ 19 cú click còn lại, bạn đã thành công rực rỡ! Đổi `droppable()` thành `concurrent()` để thấy hậu quả nhé.
