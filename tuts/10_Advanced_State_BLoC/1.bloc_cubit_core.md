# Bài 1: Quản lý Trạng thái Cấp Doanh Nghiệp (BLoC & Cubit)

Nếu Riverpod giống như một mạng lưới các dòng suối nối với nhau cực kỳ linh hoạt và hiện đại, thì BLoC (Business Logic Component) giống như một cái Pháo đài quân sự: Nguyên tắc, Kỷ luật, Thống nhất, và Dễ dàng mở rộng cho các đội ngũ hàng chục người.

> 💡 **Fun Fact:** BLoC được Google giới thiệu tại DartConf 2018. Nó tách biệt hoàn toàn Giao diện (UI) và Logic Nghiệp vụ (Business Logic) bằng kiến trúc luồng dữ liệu một chiều (Unidirectional Data Flow) dựa trên RxDart.

## 1. Tư duy của BLoC
Luồng dữ liệu của BLoC cực kỳ dễ hiểu:
UI bắn ra các SỰ KIỆN (Events). -> BLoC nhận Event, xử lý logic, gọi API. -> BLoC nhả ra TRẠNG THÁI (States). -> UI lắng nghe State và vẽ lại màn hình.

**UI không bao giờ được phép trực tiếp thay đổi State!** UI chỉ biết "Năn nỉ" (Event) BLoC thay đổi giùm.

## 2. BLoC vs Cubit (Hai anh em nhà BLoC)
- **BLoC (Event-Driven):** Bạn phải định nghĩa class Event. UI ném Event vào bằng hàm `add(MyEvent())`. Dùng cho logic cực kỳ phức tạp (VD: Luồng thanh toán đa bước, tìm kiếm).
- **Cubit (Function-Driven):** Giống BLoC nhưng rút gọn đi phần Event. UI gọi thẳng hàm của Cubit (VD: `cubit.login()`). Nhẹ nhàng, code ngắn, dùng cho 80% trường hợp bình thường.

### Cách dùng Cubit (Đơn giản hơn BLoC)
```dart
// 1. Định nghĩa State (Khuyên dùng Freezed)
class CounterState {
  final int count;
  CounterState(this.count);
}

// 2. Định nghĩa Cubit
class CounterCubit extends Cubit<CounterState> {
  // Trạng thái khởi tạo ban đầu là 0
  CounterCubit() : super(CounterState(0));

  // Hàm (Thay vì Event)
  void increment() {
    // Phát ra một state MỚI (bằng hàm emit)
    emit(CounterState(state.count + 1));
  }
}
```

### Xử lý ở UI (Dùng BlocBuilder)
```dart
BlocBuilder<CounterCubit, CounterState>(
  builder: (context, state) {
    // Mỗi khi Cubit gọi emit(), hàm builder này sẽ chạy lại
    return Text('Count: \${state.count}');
  },
)

// Khi người dùng bấm nút:
ElevatedButton(
  onPressed: () => context.read<CounterCubit>().increment(),
  child: Text('Tăng'),
)
```

## 3. BlocListener (Lắng nghe một lần)
Nếu bạn muốn hiện một cái Dialog, SnackBar, hay chuyển màn hình khi đăng nhập thành công. Bạn KHÔNG được để code chuyển màn hình trong `BlocBuilder` (Vì builder chạy nhiều lần, nó sẽ chuyển màn hình 10 lần!).
Hãy dùng `BlocListener`! Nó chỉ lắng nghe khi State thay đổi và chạy hàm ĐÚNG 1 LẦN duy nhất không vẽ UI.

## 🛑 Những nỗi đau và ngộ nhận khi còn Junior
- **Emit một State cũ:** `emit(state)`. Junior thắc mắc "Em gọi emit rồi mà giao diện không thèm Rebuild". **Cách phòng tránh:** BLoC so sánh State mới và State cũ bằng toán tử `==`. Nếu bạn đổi một thuộc tính bên trong object cũ rồi nhét nó vào `emit`, BLoC thấy 2 object CÙNG một địa chỉ bộ nhớ -> Nó cho là không có gì thay đổi. BẮT BUỘC phải tạo ra object mới (Dùng hàm `copyWith` của freezed).
- **UI có logic:** Junior hay viết `if/else` xử lý logic tính toán ngay trong nút bấm của UI rồi mới ném lên Cubit. **Cách phòng tránh:** UI phải "ngu ngốc" (Dumb UI). Tất cả não bộ tính toán phải nằm ở BLoC/Cubit.

### 🚀 Mini Pet Project: App Đếm Ngược Thần Thánh (Timer App)

**Yêu cầu:**
1. Cài đặt package `flutter_bloc`.
2. Tạo một `TimerCubit` quản lý `int` (thời gian tính bằng giây). Khởi tạo là 60.
3. Viết hàm `startTimer()`: Dùng `Timer.periodic` của Dart để mỗi 1 giây thì `emit(state - 1)`. Chú ý dừng Timer khi `state == 0`.
4. Viết hàm `resetTimer()`: `emit(60)` và hủy cái Timer cũ.
5. Giao diện: Dùng `BlocBuilder` in số giây bự chà bá giữa màn hình. Có 2 nút Start và Reset.
6. Cung cấp (Provide) cái Cubit này ở lớp ngoài cùng bằng `BlocProvider` để cả App có thể xài.
