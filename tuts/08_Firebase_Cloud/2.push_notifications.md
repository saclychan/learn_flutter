# Bài 2: Thông báo đẩy (Push Notifications)

User không mở app thì làm sao bắt user mở app? Đẩy cho họ một cái thông báo kêu "Anh ơi vào nhận voucher 100k"! Đó chính là sức mạnh của Push Notifications.

Firebase Cloud Messaging (FCM) là cầu nối miễn phí tuyệt vời nhất để bắn thông báo tới cả iOS và Android.

> 💡 **Fun Fact:** Notification trên Android hoạt động hoàn toàn miễn phí, nhưng trên iOS, bạn BẮT BUỘC phải đăng ký một tài khoản Apple Developer (99$/năm) để lấy chứng chỉ (Certificate) thì Apple mới cho phép app nhận Push.

## 1. Xin quyền nhận thông báo
Apple quy định rất nghiêm: App không được phép tự tiện bắn thông báo, phải xin phép đàng hoàng.

```dart
FirebaseMessaging messaging = FirebaseMessaging.instance;

NotificationSettings settings = await messaging.requestPermission(
  alert: true,   // Quyền hiện popup
  badge: true,   // Quyền hiện số đếm trên icon app
  sound: true,   // Quyền kêu reng reng
);

print('Quyền của user: \${settings.authorizationStatus}');
```

## 2. Bắt thông báo như thế nào?
App của bạn có 3 trạng thái sinh lý học:
- **Foreground:** User đang cầm máy, mở app nhìn chằm chằm vào.
- **Background:** App đang bị ném ra sau nền (bấm phím Home vứt đó).
- **Terminated:** Tắt cmnr (vuốt thoát app).

Với FCM, bạn phải bắt Notification ở từng trạng thái riêng biệt:

```dart
// 1. Khi đang ở Foreground
FirebaseMessaging.onMessage.listen((RemoteMessage message) {
  print('Nhận Notification lúc đang mở app: \${message.notification?.title}');
  // Lúc này ĐT không kêu tít tít tự động đâu, bạn phải dùng thư viện flutter_local_notifications để vẽ cái popup ra!
});

// 2. Khi bị ném ra Background và user bấm vào thông báo
FirebaseMessaging.onMessageOpenedApp.listen((RemoteMessage message) {
  print('User vừa nhấn thông báo: \${message.data}');
  // Điều hướng (Navigate) tới màn hình chi tiết món hàng!
});

// 3. Khi app đang bị TẮT HOÀN TOÀN
// Bạn đặt hàm này Tít trên cùng, bên ngoài hàm main()
@pragma('vm:entry-point')
Future<void> _firebaseMessagingBackgroundHandler(RemoteMessage message) async {
  print("Đang xử lý thông báo dưới nền: \${message.messageId}");
}
```

> 🧠 **Senior Detail:** Data Payload (Dữ liệu ngầm). Một cái Push Noti ngoài cái Title "Mày có người yêu mới" và Body "Vào xem ngay", nó còn có một cái cục Data ẩn (ví dụ: `{"user_id": 1234}`). Các Senior luôn dùng khối Data này để làm chức năng **Deep Navigation**: Khi user click vào thông báo, App sẽ đọc `user_id`, sau đó tự động chuyển hướng nhảy thẳng vào Màn hình Hồ sơ của người số 1234.

## 🛑 Những nỗi đau và ngộ nhận khi còn Junior
- **Cuống cuồng vì FirebaseForeground không tự hiện ra pop-up:** FCM mặc định nếu app đang mở (Foreground) thì nó KHÔNG ĐẨY pop-up xuống (khỏi làm phiền user đang xài). Junior hoang mang tưởng code lỗi. **Cách phòng tránh:** Phải kết hợp gói `flutter_local_notifications` để tự móc tay vẽ ra một cái thông báo ảo.
- **Bơm trực tiếp Push từ App Client:** Lập trình viên viết hàm bắn Push cho tài khoản B ngay trong điện thoại tài khoản A. Lộ Firebase Server Key -> Hacker lấy được Key, bắn Push quảng cáo cờ bạc cho 1 triệu Users. R.I.P. **Cách phòng tránh:** Firebase Admin SDK hoặc Firebase Cloud Functions sinh ra là để làm Backend bắn Push. Không bao giờ gửi Push từ Client.

### 🚀 Mini Pet Project: Chiến thần Push Notification

**Yêu cầu:**
1. Cài đặt package `firebase_messaging`.
2. Viết hàm xin quyền (Permission) lúc App vừa khởi động.
3. In cái FCM Token (`FirebaseMessaging.instance.getToken()`) ra Terminal.
4. Lên giao diện quản lý của Firebase Console -> Phần Messaging. Tạo một chiến dịch gửi Push mới.
5. Dán cái Token bạn vừa in ra để gửi thử (Send test message) tới điện thoại của bạn.
6. Thử 2 trường hợp: 
   - Đóng hẳn app lại -> Nhận được thông báo của hệ thống. Bấm vào mở app, in ra chữ "App được bật từ Notification".
   - (Mở rộng) Đang mở App -> In ra Terminal log `FirebaseMessaging.onMessage`.
