# Bài 3: Bố Cục (Layout) Cơ Bản & Chuyên Sâu

Chào em, layout trong Flutter thường là ác mộng của Junior với những lỗi như "Bottom overflowed by xxx pixels". Bài này sẽ giúp em làm chủ không gian màn hình với `Row`, `Column`, `Stack`, `Expanded`, và `Flexible`.

---

## 1. Mức độ Newbie: Ghép nối các khối

- **Row:** Xếp các widget theo hàng ngang.
- **Column:** Xếp các widget theo hàng dọc.
- **Stack:** Xếp các widget đè lên nhau (theo trục Z). Giống như vẽ các lớp trong Photoshop.
- **Expanded/Flexible:** Dùng bên trong Row/Column để "nở ra" chiếm phần không gian còn trống.

### Code minh họa cơ bản
```dart
Column(
  mainAxisAlignment: MainAxisAlignment.center, // Căn giữa theo trục chính dọc
  children: [
    const Text('Dòng 1'),
    Row(
      mainAxisAlignment: MainAxisAlignment.spaceAround, // Căn đều theo trục chính ngang
      children: const [
        Text('Cột 1'),
        Text('Cột 2'),
      ],
    ),
    Expanded(
      child: Container(color: Colors.blue), // Chiếm hết phần không gian còn lại
    )
  ],
)
```

## 2. Mức độ Senior: Kiến trúc Layout "Constraints go down, Sizes go up"

Câu thần chú nổi tiếng của Flutter: **"Ràng buộc truyền xuống, Kích thước truyền lên, Cha quyết định vị trí"**.

### 2.1. Quá trình tính toán Layout của RenderObject
1. Widget cha gửi một "Ràng buộc" (Constraint) xuống cho con. Ví dụ: "Con có thể rộng từ 0 đến 300px, cao từ 0 đến 500px".
2. Widget con nhìn vào ràng buộc đó, tính toán và bảo lại cha: "Con muốn rộng 200px, cao 100px".
3. Widget cha nhận kích thước của con, và quyết định: "Được, vậy con sẽ nằm ở tọa độ x=50, y=50 nhé".

### 2.2. Unbounded Constraints (Ràng buộc vô hạn)
Lỗi phổ biến nhất: Bọc một `ListView` (muốn cao vô hạn) bên trong một `Column` (cho phép con cao vô hạn). Hai "vô hạn" gặp nhau sẽ sinh ra lỗi. `Column` không biết phải cấp cho `ListView` bao nhiêu chiều cao. Giải pháp: Dùng `Expanded` để biến vô hạn thành hữu hạn (phần còn lại của màn hình).

## 3. Lời khuyên Google Style Guide
- **Không lạm dụng Container:** Nếu chỉ cần Padding, hãy dùng `Padding`. Nếu chỉ cần căn giữa, dùng `Center`. `Container` là một widget rất nặng vì cấu tạo từ nhiều thành phần kết hợp.
- **Tránh lồng ghép quá sâu (Deep nesting):** Việc lồng Row trong Column, rồi lại lồng Row... khiến code khó đọc. Hãy tách thành các custom widget.

## 4. Nỗi đau Junior (Junior Pitfalls)

❌ **Sai lầm: Bottom Overflow khi xuất hiện bàn phím hoặc màn hình nhỏ**
```dart
class MyScreen extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        Container(height: 500, color: Colors.red),
        Container(height: 500, color: Colors.green), // Lỗi tràn màn hình!
      ],
    );
  }
}
```
*Lỗi:* Màn hình điện thoại chỉ cao khoảng 800px. Khi cộng lại quá lớn, Flutter sẽ văng lỗi vạch sọc vàng đen.

✅ **Đúng: Dùng SingleChildScrollView hoặc ListView**
```dart
class MyScreen extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return SingleChildScrollView(
      child: Column(
        children: [
          Container(height: 500, color: Colors.red),
          Container(height: 500, color: Colors.green), // Vuốt để xem tiếp!
        ],
      ),
    );
  }
}
```

## 5. 🐛 Thử Thách Gỡ Lỗi (Intentional Bugs)

Màn hình dưới đây đang bị vạch sọc vàng đen với thông báo *"Vertical viewport was given unbounded height"*. Em hãy giúp anh sửa nó.

```dart
class BuggyLayout extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: Column(
        children: [
          const Text('Danh sách sinh viên:'),
          // 🐛 Lỗi ở đây! ListView lồng trong Column.
          ListView.builder(
            itemCount: 20,
            itemBuilder: (context, index) => ListTile(title: Text('SV $index')),
          ),
        ],
      ),
    );
  }
}
```
> **Gợi ý:** Làm sao để ép `ListView` chỉ chiếm phần không gian *còn lại* của `Column`? Có một Widget bắt đầu bằng chữ E.
