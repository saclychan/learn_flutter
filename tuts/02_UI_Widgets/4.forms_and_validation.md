# Bài 4: Forms và Validations (Xử Lý Biểu Mẫu)

Xin chào! Ở bài này chúng ta sẽ nói về `Form` và Text Field. Nhập liệu là thao tác cơ bản nhất khi tương tác với người dùng (Đăng nhập, Đăng ký).

---

## 1. Mức độ Newbie: TextFormField và Controller

Để cho người dùng nhập chữ, ta dùng `TextField` hoặc `TextFormField`. Để lấy chữ đó ra, ta dùng `TextEditingController`.

### Code minh họa cơ bản
```dart
class MyForm extends StatefulWidget {
  @override
  _MyFormState createState() => _MyFormState();
}

class _MyFormState extends State<MyForm> {
  final TextEditingController _controller = TextEditingController();

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        TextField(
          controller: _controller,
          decoration: const InputDecoration(labelText: 'Nhập tên'),
        ),
        ElevatedButton(
          onPressed: () {
            print('Tên bạn là: ${_controller.text}');
          },
          child: const Text('Submit'),
        )
      ],
    );
  }
}
```

## 2. Mức độ Senior: GlobalKey và Quản Lý Trạng Thái Form

Form không chỉ là để nhập chữ, nó cần phải "Validate" (kiểm tra hợp lệ) như: Email không được trống, mật khẩu phải dài hơn 6 ký tự.

### 2.1. Vai trò của GlobalKey
- `GlobalKey<FormState>` là một khóa duy nhất trên toàn ứng dụng để định danh một Form.
- Nó cho phép chúng ta từ bất kỳ đâu (ví dụ từ một nút bấm không nằm trong cây con trực tiếp của Form) gọi `_formKey.currentState!.validate()` để kiểm tra toàn bộ `TextFormField` bên trong Form đó.

### 2.2. Validation chạy như thế nào?
Khi em gọi `validate()`, Form sẽ tìm tất cả các Element chứa `FormField` trong cây con của nó, gọi hàm `validator` mà em đã cung cấp. Nếu bất kỳ validator nào trả về một `String` (chuỗi báo lỗi), Form sẽ hiện chuỗi đó màu đỏ dưới ô nhập. Nếu trả về `null`, ô đó hợp lệ.

---

## 3. Lời khuyên Google Style Guide
- **Đừng quên Dispose Controller:** `TextEditingController` nắm giữ tài nguyên hệ thống (bộ nhớ, listeners). Nếu em không gọi `_controller.dispose()` trong `dispose()` của State, app sẽ bị leak memory.
- **Sử dụng `autovalidateMode`:** Thay vì validate liên tục ngay từ đầu gây khó chịu cho user, hãy dùng `AutovalidateMode.onUserInteraction` để chỉ validate sau khi user đã bắt đầu chạm vào input.

## 4. Nỗi đau Junior (Junior Pitfalls)

❌ **Sai lầm: Viết Form rườm rà và tự quản lý lỗi bằng biến State**
```dart
// Tự tạo một đống biến kiểu bool _isEmailValid, _isPasswordValid
// Cứ mỗi khi gõ lại gọi setState để check, code dài và rối.
```

✅ **Đúng: Tận dụng Form và TextFormField**
```dart
final _formKey = GlobalKey<FormState>();

Form(
  key: _formKey,
  child: Column(
    children: [
      TextFormField(
        validator: (value) {
          if (value == null || value.isEmpty) return 'Không được để trống';
          return null;
        },
      ),
      ElevatedButton(
        onPressed: () {
          if (_formKey.currentState!.validate()) {
            // Hợp lệ, xử lý tiếp
          }
        },
        child: const Text('Login'),
      )
    ],
  ),
)
```

## 5. 🐛 Thử Thách Gỡ Lỗi (Intentional Bugs)

Đoạn code sau dùng để Submit form, nhưng có một lỗi xảy ra khi bấm Submit và người ta không thấy Validation hoạt động.

```dart
class BuggyForm extends StatelessWidget {
  final _formKey = GlobalKey<FormState>(); // 🐛 Vị trí này có ổn không?

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: Form(
        key: _formKey,
        child: Column(
          children: [
            TextFormField(
              validator: (val) => (val!.isEmpty) ? 'Trống' : null,
            ),
            ElevatedButton(
              onPressed: () {
                _formKey.currentState!.validate();
              },
              child: const Text('Check'),
            )
          ],
        ),
      ),
    );
  }
}
```
> **Gợi ý:** `GlobalKey` là một đối tượng khởi tạo 1 lần. Đặt nó trong `StatelessWidget` thì mỗi khi Widget bị rebuild, khóa cũ sẽ bị vứt đi và khóa mới được tạo, làm mất sạch trạng thái Form. Hãy đổi Widget sang dạng nào?
