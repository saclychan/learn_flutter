# Bài 1: Widget Căn Bản - Mọi thứ đều là Widget

Chào mừng em đến với thế giới của Flutter! Ở bài học đầu tiên này, chúng ta sẽ đi sâu vào triết lý cốt lõi của Flutter: **"Everything is a Widget"** (Mọi thứ đều là Widget).

---

## 1. Mức độ Newbie: Widget là gì?

Tưởng tượng Widget giống như những khối Lego. Để xây một ngôi nhà (ứng dụng), em sẽ ghép các khối Lego (Widget) lại với nhau.
- Cột nhà, mái nhà, cửa sổ -> Đều là các khối Lego.
- Nút bấm, văn bản, hình ảnh, lề (padding) -> Đều là Widget.

Trong Flutter, không chỉ các thành phần giao diện là Widget, mà ngay cả các yếu tố bố cục (layout) như `Center`, `Padding`, `Row`, `Column` cũng là Widget.

### Code minh họa cơ bản
```dart
import 'package:flutter/material.dart';

void main() {
  runApp(
    MaterialApp(
      home: Scaffold(
        appBar: AppBar(title: const Text('Widget Cơ Bản')),
        body: const Center(
          child: Text('Xin chào, đây là Widget!'),
        ),
      ),
    ),
  );
}
```

## 2. Mức độ Senior: Kiến trúc sâu bên trong

Chỉ nói "Mọi thứ đều là Widget" là chưa đủ. Để thực sự hiểu Flutter, em phải biết về 3 cây (Trees) quan trọng đằng sau giao diện:

### 2.1. Widget Tree
- Là cấu hình tĩnh của giao diện.
- Nó **nhẹ** và **bị hủy/tạo lại liên tục** mỗi khi `build()` được gọi.
- Bản chất Widget chỉ là các class chứa data config, không trực tiếp vẽ lên màn hình.

### 2.2. Element Tree
- Là sự kết nối giữa Widget và RenderObject.
- Khi Flutter tạo một Widget, nó sẽ gọi `Widget.createElement()` để tạo ra một Element tương ứng.
- Element quản lý vòng đời (lifecycle) và là nơi nắm giữ `BuildContext` thực chất.
- **BuildContext** chính là một đối tượng Element! Khi truyền `context` vào hàm build, thực chất em đang truyền vị trí của Widget đó trong Element Tree.

### 2.3. RenderObject Tree
- Là cây chịu trách nhiệm tính toán kích thước (layout), vẽ (paint), và lắng nghe sự kiện chạm (hit-testing).
- Rất **nặng** và tốn tài nguyên. Flutter cố gắng tái sử dụng (reuse) RenderObject thay vì tạo lại mỗi khi Widget rebuild.

**Senior Detail:** 
> Khi Widget thay đổi (vd `setState`), Flutter so sánh Widget Tree mới và cũ. Nếu loại Widget và `Key` không đổi, Element sẽ được giữ lại (reuse) và cập nhật RenderObject tương ứng (chỉ gọi updateRenderObject). Quá trình này giúp Flutter render với tốc độ 60fps hoặc 120fps.

## 3. Lời khuyên Google Style Guide
- **Sử dụng `const` constructor**: Bất cứ khi nào Widget không thay đổi, hãy thêm từ khóa `const`. Điều này giúp Flutter biết rằng Widget này không cần tạo lại khi rebuild, tối ưu đáng kể Element Tree.
- **Tách nhỏ Widget thay vì dùng Helper Method**: Không nên viết hàm trả về Widget (vd `Widget buildMyButton()`). Hãy tạo class kế thừa `StatelessWidget`. Tại sao? Vì class có context riêng và Element riêng, giúp so sánh hiệu quả hơn và không kéo theo việc rebuild cả trang lớn.

## 4. Nỗi đau Junior (Junior Pitfalls)

Nhiều Junior thường nhồi nhét tất cả UI vào trong một file hoặc một hàm `build()` khổng lồ dài hàng ngàn dòng.

❌ **Sai lầm: Dùng hàm trả về Widget để tách code**
```dart
class MyScreen extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        _buildHeader(), // Hàm này rebuild theo MyScreen
        _buildBody(),
      ],
    );
  }

  Widget _buildHeader() {
    return Container(
      color: Colors.blue,
      child: Text('Header'),
    );
  }
}
```

✅ **Đúng: Tách ra thành Class**
```dart
class MyScreen extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        const HeaderWidget(), // Có thể dùng const, có Element riêng
        // body...
      ],
    );
  }
}

class HeaderWidget extends StatelessWidget {
  const HeaderWidget({Key? key}) : super(key: key);

  @override
  Widget build(BuildContext context) {
    return Container(
      color: Colors.blue,
      child: const Text('Header'),
    );
  }
}
```
*Lý do:* Tách class giúp Flutter cache lại Widget nếu là `const`, và chỉ rebuild đúng phần cần thiết.

## 5. 🐛 Thử Thách Gỡ Lỗi (Intentional Bugs)

Dưới đây là một đoạn code đang bị lỗi giao diện. Màn hình chỉ hiện một mảng màu trắng xoá và console báo lỗi về "Directionality". Em hãy tự sửa nó.

```dart
import 'package:flutter/material.dart';

void main() {
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({Key? key}) : super(key: key);

  @override
  Widget build(BuildContext context) {
    // 🐛 Lỗi nằm ở đâu? Gợi ý: Các widget text cần biết hướng chữ (LTR hay RTL)
    return Column(
      children: const [
        Text('Hello, Bug!'),
      ],
    );
  }
}
```
> **Gợi ý gỡ lỗi:** Em đã quên bọc bằng `MaterialApp` hoặc một Widget cung cấp `Directionality`. Hãy thử thêm `MaterialApp` hoặc bọc `Directionality` xem sao!
