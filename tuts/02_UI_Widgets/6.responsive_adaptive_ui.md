# Bài 6: Responsive & Adaptive UI

Lập trình Flutter có nghĩa là code 1 lần chạy trên Mobile, Web, Desktop, Tablet. Bài này sẽ hướng dẫn cách làm UI co giãn (Responsive) và thích nghi (Adaptive) với mọi kích thước.

---

## 1. Mức độ Newbie: MediaQuery và LayoutBuilder

Làm sao để biết màn hình đang to hay nhỏ?
- **MediaQuery:** Cung cấp thông tin kích thước toàn màn hình (Screen size).
- **LayoutBuilder:** Cung cấp thông tin kích thước của Widget cha truyền xuống (Constraints).

### Code minh họa cơ bản
```dart
class ResponsiveScreen extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    final screenWidth = MediaQuery.of(context).size.width;

    return Scaffold(
      body: Center(
        child: Text(screenWidth > 600 ? 'Màn hình LỚN' : 'Màn hình NHỎ'),
      ),
    );
  }
}
```

## 2. Mức độ Senior: Kiến trúc hệ thống Design

Thay vì IF-ELSE bừa bãi khắp nơi bằng MediaQuery, một Senior sẽ dựng kiến trúc đàng hoàng.

### 2.1. Phân loại Breakpoints
Thường ta chia ra 3 mốc: Mobile (< 650px), Tablet (650 - 1100px), Desktop (> 1100px).
Tạo một helper class:
```dart
class ResponsiveWidget extends StatelessWidget {
  final Widget mobile;
  final Widget tablet;
  final Widget desktop;

  const ResponsiveWidget({required this.mobile, required this.tablet, required this.desktop});

  @override
  Widget build(BuildContext context) {
    return LayoutBuilder(
      builder: (context, constraints) {
        if (constraints.maxWidth >= 1100) return desktop;
        if (constraints.maxWidth >= 650) return tablet;
        return mobile;
      },
    );
  }
}
```

### 2.2. Adaptive vs Responsive
- **Responsive:** Giao diện TỰ CO GIÃN (Ví dụ cột chuyển thành hàng khi xoay ngang máy).
- **Adaptive:** Giao diện THAY ĐỔI COMPONENT để hợp với nền tảng (Ví dụ: trên iOS dùng `CupertinoSwitch`, trên Android dùng `Switch` Material).

## 3. Lời khuyên Google Style Guide
- **Ưu tiên LayoutBuilder hơn MediaQuery:** Khi thiết kế một custom widget, hãy để nó tự co giãn theo khoảng trống cha cấp cho nó (`LayoutBuilder`), thay vì dựa vào toàn bộ màn hình (`MediaQuery`). Điều này giúp Widget có thể tái sử dụng ở bất kỳ vị trí nào!

---

## 4. Nỗi đau Junior (Junior Pitfalls)

❌ **Sai lầm: Dùng MediaQuery mọi nơi khiến Widget bị Rebuild liên tục**
Khi bàn phím xuất hiện, chiều cao màn hình thay đổi, `MediaQuery.of(context).size` thay đổi, khiến TẤT CẢ widget xài nó bị rebuild từ đầu chí cuối dù không liên quan.

✅ **Đúng: Dùng MediaQuery.sizeOf(context)**
```dart
// Thay vì:
final size = MediaQuery.of(context).size;

// Hãy dùng (từ Flutter 3.10):
final width = MediaQuery.sizeOf(context).width; 
// Giúp chỉ lắng nghe kích thước, không lắng nghe các yếu tố khác (như bàn phím, padding)
```

## 5. 🐛 Thử Thách Gỡ Lỗi (Intentional Bugs)

Màn hình dưới đây muốn hiện chữ theo màu, nhưng khi chạy trên Desktop (màn hình rộng), app lại crash vì lỗi RenderFlex.

```dart
class BuggyResponsive extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: Row(
        children: [
          Container(width: 500, color: Colors.blue),
          // 🐛 Lỗi ở đây! Nếu màn nhỏ hơn 1000, tổng là 1000 > màn hình => LỖI!
          Container(width: 500, color: Colors.red), 
        ],
      ),
    );
  }
}
```
> **Gợi ý:** Làm sao để nếu màn hình không đủ 1000px, nó tự bọc xuống hàng dưới thay vì cố chen chúc trên 1 hàng? Hãy thử đổi `Row` thành `Wrap`.

## 6. 🚀 Mini Pet Project

**Yêu cầu:** 
Làm một trang "Dashboard":
1. Dùng `LayoutBuilder` để phát hiện chiều rộng.
2. Nếu dưới 600px (Mobile): Hiển thị `Column` chứa 2 khối màu (VD: Xanh lá, Vàng).
3. Nếu từ 600px trở lên (Tablet/Web): Hiển thị `Row` chứa 2 khối màu đó chia đều màn hình (dùng `Expanded`).
4. Hãy thử xoay màn hình điện thoại (nếu dùng máy ảo) hoặc resize cửa sổ web để thấy giao diện tự nhảy!
