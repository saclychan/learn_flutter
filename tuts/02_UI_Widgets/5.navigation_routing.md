# Bài 5: Navigation & Routing (Điều Hướng)

Khi app lớn lên, em không thể nhồi nhét tất cả vào một màn hình được. Bài này hướng dẫn cách chuyển qua lại giữa các màn hình.

---

## 1. Mức độ Newbie: Đẩy và Pop

Trong Flutter, điều hướng hoạt động theo cơ chế **Ngăn xếp (Stack)**.
- `Navigator.push`: Mở một trang mới đè lên trang hiện tại (Thêm đĩa vào ngăn xếp).
- `Navigator.pop`: Đóng trang hiện tại và quay về trang trước đó (Rút đĩa ra khỏi ngăn xếp).

### Code minh họa cơ bản
```dart
// Mở trang mới
Navigator.push(
  context,
  MaterialAppPageRoute(builder: (context) => const DetailScreen()),
);

// Trở về
Navigator.pop(context);
```

---

## 2. Mức độ Senior: Named Routes & Navigator 2.0 / Router API

Khi app có hàng chục màn hình, dùng `push` với `MaterialPageRoute` rất dễ lỗi. Chúng ta cần định tuyến bằng tên (Named Routes).

### 2.1. Named Routes (Navigator 1.0)
Định nghĩa bảng `routes` trong `MaterialApp`:
```dart
MaterialApp(
  initialRoute: '/',
  routes: {
    '/': (context) => const HomeScreen(),
    '/detail': (context) => const DetailScreen(),
  },
)
// Chuyển trang: Navigator.pushNamed(context, '/detail');
```

### 2.2. GoRouter (Thay thế cho Navigator 2.0)
Navigator 2.0 (Router API) của Flutter rất mạnh mẽ nhưng cực kỳ phức tạp (phải xử lý Parser, Delegate...). Google khuyến nghị sử dụng package `go_router` làm tiêu chuẩn mới. Nó hỗ trợ Deep Linking (Mở app từ link web) cực kỳ dễ dàng.

**Senior Detail:** 
> GoRouter sử dụng cơ chế Declarative (Khai báo), thay vì Imperative (Ra lệnh) của Navigator 1.0. Điều này giúp giữ trạng thái URL web đồng bộ hoàn toàn với màn hình App.

## 3. Lời khuyên Google Style Guide
- **Đừng dùng chuỗi cứng (Hardcode strings):** Khi dùng Named Routes, đừng gõ chữ `'/detail'` khắp nơi. Hãy định nghĩa một biến static `static const String routeName = '/detail';` bên trong class Screen đó.
- **Truyền dữ liệu rõ ràng:** Nếu màn B cần dữ liệu từ màn A, hãy truyền qua Constructor, thay vì nhét mọi thứ vào tham số động (arguments) khó kiểm soát kiểu dữ liệu.

## 4. Nỗi đau Junior (Junior Pitfalls)

❌ **Sai lầm: Lỗi "Navigator operation requested with a context that does not include a Navigator."**
Lỗi này xảy ra khi em gọi `Navigator.push(context)` tại cùng nơi em khai báo `MaterialApp`. Tại vì context này là "cha" của MaterialApp, nó chưa hề biết Navigator là cái gì (Navigator được sinh ra BÊN TRONG MaterialApp).

✅ **Đúng: Tách ra Widget con hoặc dùng Builder**
```dart
// Sai:
runApp(MaterialApp(
  home: Scaffold(
    body: Builder(
      builder: (context) => ElevatedButton(
        // Đúng: context này được sinh ra TỪ Scaffold, nằm trong MaterialApp
        onPressed: () => Navigator.push(...), 
      ),
    ),
  ),
));
```

## 5. 🐛 Thử Thách Gỡ Lỗi (Intentional Bugs)

Dưới đây là một hệ thống route, nhưng khi chạy nó bị văng app (crash) ngay lúc khởi động.

```dart
void main() {
  runApp(
    MaterialApp(
      home: const HomeScreen(),
      initialRoute: '/', // 🐛 Lỗi liên quan đến home và initialRoute
      routes: {
        '/': (context) => const HomeScreen(),
        '/second': (context) => const SecondScreen(),
      },
    ),
  );
}
```
> **Gợi ý:** Flutter không cho phép em định nghĩa CẢ `home` LẪN `initialRoute: '/'`. Em hãy chọn một trong hai!
