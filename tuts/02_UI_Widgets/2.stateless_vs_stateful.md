# Bài 2: Stateless vs Stateful Widget

Chào em, ở bài trước ta đã biết "Mọi thứ đều là Widget". Bài này ta sẽ tìm hiểu 2 loại Widget cốt lõi nhất cấu thành nên 90% giao diện: **StatelessWidget** và **StatefulWidget**.

---

## 1. Mức độ Newbie: Trạng thái (State) là gì?

- **StatelessWidget (Không trạng thái):** Là những Widget một khi đã vẽ lên thì không thay đổi nữa. Ví dụ: Một dòng chữ mô tả ứng dụng, một Icon trang trí tĩnh.
- **StatefulWidget (Có trạng thái):** Là những Widget có thể thay đổi dữ liệu và vẽ lại (rebuild) chính nó khi dữ liệu đó đổi. Ví dụ: Một Checkbox (đổi từ chưa tick sang đã tick), Một bộ đếm (tăng từ 0 lên 1, 2, 3).

### Code minh họa cơ bản
```dart
// StatelessWidget
class MyText extends StatelessWidget {
  final String text;
  const MyText(this.text, {Key? key}) : super(key: key);

  @override
  Widget build(BuildContext context) {
    return Text(text);
  }
}

// StatefulWidget
class Counter extends StatefulWidget {
  @override
  _CounterState createState() => _CounterState();
}

class _CounterState extends State<Counter> {
  int _count = 0;

  void _increment() {
    setState(() {
      _count++;
    });
  }

  @override
  Widget build(BuildContext context) {
    return ElevatedButton(
      onPressed: _increment,
      child: Text('Count: $_count'),
    );
  }
}
```

## 2. Mức độ Senior: Vòng đời (Lifecycle) và Tối ưu

### 2.1. Vòng đời của StatefulWidget (Lifecycle)
Với StatefulWidget, đối tượng `State` có một vòng đời khắt khe. Các hàm quan trọng:
- `initState()`: Gọi DUY NHẤT 1 LẦN khi State được khởi tạo. Nơi lý tưởng để khởi tạo biến, đăng ký stream, listener.
- `didChangeDependencies()`: Gọi ngay sau `initState` và khi các *Dependency* (ví dụ InheritedWidget/Provider) thay đổi.
- `build()`: Gọi nhiều lần. Mỗi khi gọi `setState`, `build` sẽ chạy lại. Hãy giữ hàm này nhẹ nhất có thể!
- `didUpdateWidget()`: Gọi khi Widget cha rebuild và truyền config (properties) mới xuống cho Widget này.
- `dispose()`: Gọi khi State bị hủy hoàn toàn khỏi Element Tree. Rất quan trọng để hủy các Stream, AnimationController để tránh rò rỉ bộ nhớ (memory leak).

### 2.2. Tối ưu Rebuild với setState
- Lệnh `setState((){})` báo cho Element biết State đã bị dirty và đánh dấu cần chạy lại `build()`.
- **Senior Detail:** Đừng gọi `setState` ở Widget trên cùng (ví dụ `MyApp` hoặc cả một màn hình to đùng) nếu chỉ một nút bấm nhỏ thay đổi! Việc này khiến toàn bộ Element Tree bên dưới phải so sánh (diff) gây hao tốn tài nguyên. Hãy cô lập (isolate) các StatefulWidget nhỏ lại ở chỗ cần thay đổi.

## 3. Lời khuyên Google Style Guide
- **Sử dụng private variables cho State:** Thuộc tính của State class nên để dạng private (thêm dấu `_` đằng trước, vd `int _counter`).
- **Phân tách State class và Widget class:** Luôn giữ class `State` cùng file hoặc private, không export nó ra ngoài cho nơi khác gọi (vd `class _MyWidgetState extends State<MyWidget>`).

## 4. Nỗi đau Junior (Junior Pitfalls)

❌ **Sai lầm: Quên dọn dẹp tài nguyên gây Memory Leak**
```dart
class _MyTimerState extends State<MyTimerWidget> {
  Timer? _timer;

  @override
  void initState() {
    super.initState();
    _timer = Timer.periodic(const Duration(seconds: 1), (timer) {
      print('Tick!'); // Vẫn in ra dù màn hình đã bị đóng
    });
  }

  // Quên override dispose để cancel timer!
}
```

✅ **Đúng: Dọn dẹp cẩn thận trong `dispose`**
```dart
class _MyTimerState extends State<MyTimerWidget> {
  Timer? _timer;

  @override
  void initState() {
    super.initState();
    _timer = Timer.periodic(const Duration(seconds: 1), (timer) {
      //...
    });
  }

  @override
  void dispose() {
    _timer?.cancel(); // Phải hủy!
    super.dispose();
  }
}
```

## 5. 🐛 Thử Thách Gỡ Lỗi (Intentional Bugs)

Dưới đây là một bộ đếm đếm số lần bấm, nhưng mỗi khi bấm, số đếm không hề thay đổi trên màn hình. Gợi ý: Có gì đó sai ở hàm `onPressed`.

```dart
class BadCounter extends StatefulWidget {
  @override
  _BadCounterState createState() => _BadCounterState();
}

class _BadCounterState extends State<BadCounter> {
  int _count = 0;

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: Center(
        child: Text('Đã bấm: $_count lần'),
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: () {
          // 🐛 Lỗi nằm ở đâu? 
          _count++;
        },
        child: const Icon(Icons.add),
      ),
    );
  }
}
```
> **Gợi ý:** Flutter không biết khi nào biến `_count` thay đổi để vẽ lại giao diện đâu em! Hàm thần thánh nào bị thiếu?

## 6. 🚀 Mini Pet Project

**Yêu cầu:** Tạo một ứng dụng "Đèn Giao Thông" nhỏ:
1. Màn hình có một khối hình tròn (dùng `Container` có decoration hình tròn).
2. Có một nút bấm "Đổi màu đèn".
3. Mặc định đèn màu Đỏ. Khi bấm nút, đèn chuyển sang Xanh -> Vàng -> Đỏ theo vòng lặp.
4. *Bonus point (Thêm điểm nâng cao):* Viết hàm `initState` in ra console "Khởi tạo đèn" và `dispose` in ra "Đã hủy đèn".
